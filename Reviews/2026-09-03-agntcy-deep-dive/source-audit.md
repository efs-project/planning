## Governance, identity, runtime and standards

- **Governance:** [adopted charter](https://github.com/agntcy/governance/blob/02a14eb4eb771f74c13d612b18b69b00ea3f7b32/CHARTER.pdf), AGNTCY/LF, 2025-07-22, establishes actual voting rules. The older [Operating Model](https://github.com/agntcy/governance/blob/02a14eb4eb771f74c13d612b18b69b00ea3f7b32/OPERATING_MODEL.md) “TBD” wording must not override it. The contributor definition of adopter includes using and/or evangelizing; do not count logos as measured deployments.
- **Identity revocation exists:** [Identity Node VC service](https://github.com/agntcy/identity/blob/452077220fc5b7c5c5198251b945df5fe61628f2/internal/node/vc_service.go) and [Identity Service revoker](https://github.com/agntcy/identity-service/blob/b46dcd6da72a78c05ca0c1857fa4e72c5ef0d189/backend/internal/core/badge/revoker.go). [CLI verification](https://github.com/agntcy/identity/blob/452077220fc5b7c5c5198251b945df5fe61628f2/internal/issuer/verify/service.go) resolves configured node metadata; embedded-proof verification unsupported there. Freshness for old downloaded badges, node consistency and stable-ID lost-key recovery remain untested.
- **SLIM:** [authentication](https://slim.agntcy.org/latest/slim/architecture/authentication/), [naming](https://slim.agntcy.org/latest/slim/architecture/naming/), [session persistence](https://slim.agntcy.org/latest/slim/components/sdk/tutorials/tutorial-persistence/), checked Sep3. Transport/workload credentials and recoverable group sessions are not general globally published agent memory.
- **SHADI:** [local SQLCipher memory code](https://github.com/agntcy/shadi/blob/3c712854a5e8999b5c6f9dc3f34fedb276ce105e/crates/shadi_memory/src/lib.rs) has scoped put/get-latest/search/list/delete. Current source has no `soul` match; that is bounded negative evidence, not proof that no extension could carry one. Early version and runtime security were not independently validated.
- **AI Catalog/ARD:** [AGNTCY June17 v1.5 announcement](https://github.com/agntcy/dir/discussions/1673) establishes implementation coordination; [AI Catalog governance](https://github.com/Agent-Card/ai-catalog/blob/main/GOVERNANCE.md) is separate. [ARD v0.91 Proposal](https://agenticresourcediscovery.org/spec/), Aug26, and [governance](https://agenticresourcediscovery.org/governance/) remain evolving; do not promise latest-version compatibility or treat its hosting decision as AGNTCY's LF governance.
- **Adoption:** [Webex product account](https://developer.webex.com/blog/webex-leverages-agntcy-directory-and-identity-for-agentic-apps), Kriti Jain, Feb27, is first-party implementation evidence. Federation scale, independent operators, usage and availability were not measured.

## Search log and stopping rule

Discovery covered official AGNTCY/Directory/OASF documentation; release/tag histories; Agent Skills specification; Identity/SLIM/SHADI; LF charter/history; IETF ADS/SLIM status; AI Catalog/ARD; and existing EFS/NANDA planning. Dependent source audits traced storage→identity→resolution, import→artifact→export/install, and issuer→verification→revocation rather than relying on landing-page claims.

Corrected initial hypotheses: metadata-only is false; bundle support is not main-only; “unsupported schema bypasses validation” is not the observed SDK behavior; Identity has revocation; SHADI has memory/runtime; formal governance voting rules exist; federation and content IDs alone do not establish shared authoritative current state.

Remaining gaps require executable fixtures or real adopter interviews, not more similar web searches. No runtime tests, native agent installs, benchmark or security exploit reproduction were performed. Private temporary clones were used only for source inspection; no third-party source or downloaded skill corpus was copied into EFS.
