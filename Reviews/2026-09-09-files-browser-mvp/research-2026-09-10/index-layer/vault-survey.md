# Vault survey: separate/retroactive/crowd-built index layer

## 1. How the v1 sort overlay actually worked

**Who declares.** A sort concept is a naming ANCHOR (`anchorSchema = SORT_INFO_SCHEMA_UID`) under the parent or under the global `/sorts/`; any attester then attests a SORT_INFO (`address sortFunc, bytes32 targetSchema, uint8 sourceType`) whose `refUID` is that naming anchor — "the SORT_INFO is the per-attester implementation detail" (`$C/specs/07-Sort-Overlay-Architecture.md:36-46`). Which implementation a reader uses is resolved through the lens list, first non-revoked wins (`:52-60`, `:73-80`, `:298-306`). System sorts ByName/ByDate are deployer-attested at deploy (`:253-262`). SDK surface: `efs.sorts.declare/list/default/setDefault` (`$V/Designs/sdk-architecture.md:592-614`).

**Who pays.** "Sorts are lazily populated: items are inserted one batch at a time by any caller, who pays the gas" (`spec 07:5`); the list is keyed `(sortInfoUID, parentAnchor)`, **not per attester** — "Gas spent processing a sort is a public good" (`:9-13`, `:313`). Per-attester views are a read-time filter over the shared list (`getSortedChunkByAddressList` + `containsAttestations`, `:147-161`). The SDK codifies "any caller can advance any sort, so a reader can also bring a stale list current itself" (`sdk-architecture.md:583`). Auto-processing after upload is deliberately limited to the active sort only, to stop troll-sort wallet-prompt spam (`spec 07:277-283`).

**How chunks are verified (trusted nothing).** `processItems(sortInfoUID, parent, expectedStartIndex, items[], leftHints[], rightHints[])` (`$C/packages/hardhat/contracts/EFSSortOverlay.sol:205-258`):
- each item must equal the kernel array element at the current index — `if (item != expected) revert InvalidItem()` (`:235-236`; spec `:103`, `:289`) — so callers cannot inject UIDs;
- position hints are validated by the sort function's `isLessThan` on both sides — `InvalidPosition` (`:251-252`; spec `:105`); comparison work is pushed off-chain, the contract does O(1) validation per item (`sdk-architecture.md:641`);
- empty sort key ⇒ item skipped but index advanced (`:246-248`); revoked items are always inserted and hidden at read (`spec 07:109`, `:266-273`);
- concurrency: `currentIndex >= expectedStartIndex + items.length` ⇒ silent no-op (front-run callers succeed); `currentIndex != expectedStartIndex` ⇒ `revert StaleStartIndex` (`:221-227`; spec `:97-100`); reentrancy guard because `ISortFunc` is caller-supplied code (`:44-49`);
- the SDK hides both races ("refresh+retry / silent success, never surfaced as errors", `sdk-architecture.md:896-897`, `:626-635`).

**How staleness is represented.** One watermark per list: `_lastProcessedIndex[sortInfoUID][parentAnchor]` (`EFSSortOverlay.sol:128`, `:257`); `getSortStaleness = kernelCount − lastProcessedIndex` (`:622-631`; spec `:169-179`); `getLastProcessedIndex` is the CAS value (`:638`). The watermark is in **kernel-array-index units** (the parent's `_children` or `_childrenBySchema` position per `sourceType`), i.e. a per-directory ordinal — the same shape v2's kind-10 scope ordinal gives per principal.

**How readers know completeness — they mostly don't.** `getSortedChunk` returns `(items, nextCursor)`; `nextCursor == 0` means end of the *overlay list*, not "overlay covers the kernel"; a `maxTraversal` hit returns a partial page with a non-zero cursor (`spec 07:133-165`). Completeness versus the kernel requires a *separate* `getSortStaleness` call; nothing binds the two, so a client mixing them across blocks gets a phantom/ghost (the exact one-basis hazard v2 later names, `$V/Reviews/2026-08-13-efs2-stage-a-corpus/chapters/b0-indexes.md:1354-1362`). Two concrete silent-absence defects in the v1 design itself:
1. `getSortStaleness` returns **0 for an unknown or revoked SORT_INFO** (`EFSSortOverlay.sol:623-624`) while the SDK documents "0 = fully sorted" (`sdk-architecture.md:623-624`) — a revoked sort reads as complete.
2. The list never shrinks: removals are a no-op for the overlay, "staleness and traversal cost don't shrink" (`sdk-architecture.md:566-568`; ADR-0009).

**Status.** SORT_INFO is deferred from the frozen nine (`$C/specs/overview.md` schema table; `sdk-architecture.md:829-830`, `:1375`); the `sourceType` field string was inconsistent across specs 02/06/07 (`sdk-architecture.md:643`; `$C/docs/FUTURE_WORK.md:568`); `EFSSortOverlay` is "wired into EFSIndexer, not redeployable" (`overview.md` core-contracts table) and changing it orphans `SORT_INFO_SCHEMA_UID` — an Etched change (`FUTURE_WORK.md:559`). Lens-scoped list sorting via the overlay was investigated and rejected 2026-05-31 ("it breaks the lens waterfall", "no consumer", comparator OOG risk; decision: client-side `weight` PROPERTY sort, `FUTURE_WORK.md:552-566`). Scaling gap: sequential-only pagination past 10K items (`FUTURE_WORK.md:319-321`). There is **no dedicated v1 ADR for the sort overlay** — the six ADR grep hits are incidental mentions; `$C/AGENTS.md` routes it to "ADR-0011 (transports pattern analog), specs/07".

## 2. Every place the vault discusses later-added or crowd-built indexes/views, and what it concluded

## 3. Carrying an "index complete through ordinal N" watermark in the current vocabulary

**What exists.** `Completeness {UNKNOWN=0, COMPLETE, PARTIAL, UNSUPPORTED}` and `PageResult {realmBasis, highWaterOrdinal, cursor, items, coverage, completeness}` (`$V/Reviews/2026-09-05-c0-core/src/StateAuditPages.sol:14-30`; `b0-indexes.md:1993`). Rules (`b0-indexes.md:1321-1366`): never-empty (truncation ⇒ PARTIAL+cursor, even with zero items); UNSUPPORTED for any undeclared index, "never confused with a declared-but-empty one"; UNKNOWN reserved, "Core never emits it… never grounds absence"; one-basis discipline (page 1 returns `H`, every later page and point read pins `basisOrdinal = H`); `coverage` = examined-entry count. Constitution: every enumeration exposes "Realm, policy/code basis, high-water mark, cursor, coverage, and COMPLETE/PARTIAL/UNSUPPORTED/UNKNOWN… `UNKNOWN` is never absence" (`$V/Designs/efsv2/system-constitution.md:207-209`). Point results `FOUND|ABSENT_PROVEN|UNKNOWN|CONFLICT`; merged `ABSENT_PROVEN` only if every input is complete at the same basis and domain, any PARTIAL ⇒ UNKNOWN (`$V/Designs/efsv2/disposable-mvp-profile.md:615-632`); composite completeness = minimum over members (`$V/Designs/efsv2/lens-spec.md:63`).

**Two ordinals, not one.** `highWaterOrdinal` is the *admission basis* (what the ledger holds at H). An "indexed through N" watermark is a *coverage* fact about a derived structure: F4 already separates them as `backfillThroughOrdinal` (historical partition) plus `liveFromOrdinal` (live partition maintained by the write path), and defines: COMPLETE at basis H iff profile COMPLETE and `backfillThrough ≥ min(H, historicalEnd)`; otherwise PARTIAL with `[1, backfillThroughOrdinal]` reported (`b0-indexes.md:1978-1984`). So the watermark rides in the **report struct beside the enum**, and the enum stays four-valued. Cursors additionally commit `coverageRevision` so a backfill step between pages invalidates rather than splices (`:1958-1960`) — the same role `expectedStartIndex`/`StaleStartIndex` plays for v1 writers.

**Unit of the watermark depends on the family.** Global families (kind 1–7, 9) scan the admission log, so N is a global admission ordinal (`b0-indexes.md:428-446`, `:819-832`). Directory-local bitmap families are keyed by the per-principal kind-10 ordinal, so N must be `throughOrdinal[scope][attester][family]` in *scope-local* units — one stamp per column, not per column-set (judge `:30`, `:224`); the v1 overlay's `_lastProcessedIndex[sortInfoUID][parent]` is precisely this shape in kernel-array units. A Lens over k principals therefore composes k watermarks by minimum (`lens-spec.md:63`).

**Sub-reason gap.** The enum cannot distinguish PARTIAL-because-truncated (resume the cursor) from PARTIAL-because-not-yet-indexed (someone must pay to advance N). F4 surfaces it via `profile.state`; the enum itself does not. The v1 SDK had the same hole in the other direction (`staleness()` separate from `read()`).

**Runtime shape, measured.** On the files-browser branch every shipped silent-absence bug was aggregate-level — "rows read with no coverage check", "stale PRIOR_SEALED rows" compile clean while point-level unions catch `?.items ?? []` (`$V/Reviews/2026-09-09-files-browser-mvp/report-for-codex-2026-09-10.md:18-24`); the composition of the machine broke when "a merge emitted absence from empty PARTIAL pages" (`…/report-for-codex.md:37-40`). The measured fix ordering is runtime absence > type unions > lint > docs (`/Users/james/.claude/projects/-Users-james-Code-EFS/memory/efs-silent-absence-is-a-shape-problem.md`): a watermarked result must make `rows` unreachable unless `throughOrdinal ≥ basis` — the watermark cannot be a sibling field the caller may ignore.

## 4. Constraints any retroactive index must satisfy

1. **Authorship boundary.** "Nobody else may author" (`tag-system:156-158`): a retroactive writer is (a) the principal, (b) a delegate the principal bound on-chain (`TAG_VOCAB_DELEGATE`, graph-native `:149`), or (c) a structure attributable to *no* principal — a derived index keyed by its own identity over kernel facts, with principal filtering at read time. v1's shared `(sortInfoUID, parent)` list is (c) (`spec 07:11-13`); ADR-0066 is the kernel-level version of the same rule (discovery may not write placement). Payer and authoriser must be separate fields (judge `:29`; graph-native "signed by V, paid by anyone").
2. **Ordinal verification, per bit.** Contracts probe bits without hydrating, so every retroactive bit must be verified against the kernel at write (`tag-system:158-161`, ≈8,400 gas ESTIMATED); v1 did exactly this with `item == kernelArray[currentIndex]` (`EFSSortOverlay.sol:235-236`). A fold that copies from an already-verified column (`implied |= assert`) inherits verification; a fold that recomputes from bodies does not and must re-verify.
3. **Deterministic from state-readable facts.** Reconstruction promise (`system-constitution.md:210-216`); the v1 property "wrong combos waste the caller's own gas, no harm to others" (`spec 07:293`) only holds because hints are validated by `isLessThan`, not trusted. Scan source must exist: the admission log for global families (`b0-indexes.md:428-446`), the kind-10 list per scope; there is **no** "which scopes contain A" map, so per-scope only (`graph-native:153`; `booru-faithful:183`).
4. **Derived ≠ asserted.** Separate family, never mixed into a principal's asserted column (e621 lesson, `graph-native:147-155`); removal is a recompute, not a word-wise subtraction.
5. **Never absence while incomplete.** AA-5/GATE_4; "Mutable 'add an index later' cannot imply complete historical absence" (`core-architecture-candidate.md:325`); UNSUPPORTED for undeclared, PARTIAL with explicit `[1,N]` while backfilling, merged absence needs every input COMPLETE at one basis. An effectful contract consumer pins the exact profile/Type (`layered:400-402`; consumer-tournament verdict), so a later index is a *new pinned identity*, never a mutable "latest".
6. **Watermark mechanics.** CAS on the expected next ordinal (v1 `StaleStartIndex`; F4), bounded units per call (v1 `maxBatch`; F4 16 admissions; folds by word range like `tickBitmap`, `indexing.md:145`), backfill mints no ordinal, cursors bind the coverage revision, historical/live partition so live writes never race the backfill (F4 `liveFromOrdinal = d+1`; v1 needs no partition because kernel order *is* scan order and staleness simply grows). Watermarks must be spine ordinals, never max-seen heads (W1, `attack-boundary-os.md:74-78`).
7. **Append-only discipline.** No writes into existing append-only families (ADR-0009; agent-workflow Tier-1); a retroactive index is always a *new* structure. v1 overlay storage never shrinks (`sdk-architecture.md:567-568`).
8. **Reader paired with every writer, watermark in the same result.** "Every write gate must have a reader" (`graph-native:123`; `/Users/james/.claude/projects/-Users-james-Code-EFS/memory/efs-confirms-but-unreadable-class.md`); the v1 `staleness()`/`read()` split and the revoked-sort-reads-as-complete defect (§1) are the counterexamples.
9. **Cost envelope.** Fresh word 22,100 today / 110,020 Glamsterdam, rewrite 5,000 / 12,100 (QUOTED/ESTIMATED); per-256-entry fold 9,200–26,300 / 16,300–114,220 (ESTIMATED); EIP-7825 16,777,216 per tx; reads ~100× writes, so lazy aggregates (§8.3) and read-time expansion are the default and write-time materialisation is the opt-in for low-fan-in probes contracts must run in-tx (`tag-system:163-170`).
10. **Griefing shape carried from v1.** Troll declarations are cheap (spec 07 `:281`, `:291`); a `UnnecessaryReposition`-style no-op guard and "only the active sort auto-processes" are the v1 mitigations; v2 has none recorded for volunteer index declarations beyond "writers pay" (`b0-indexes.md:1128-1130`).
