### 1.2 Investigated (survived adversarial passes — all July 2026, all now "evidence" after the greenfield reset)

- **ANCHOR-as-object dropped; thin TAGDEF record kept.** `tagId = keccak(DOMAIN, parentTagId, keccak(name), kind)`; hierarchy falls out of the derivation; rename/subsume = REDIRECT over immutable ids; "is X under /pizza" = walk `_parents`. The red-team caveat: a bare tagId is unverifiable (keccak one-wayness), so the per-segment record carries on-chain canonical-name validation and path permanence. `Designs/efsv2/fable-handoff-v2-tag-core.md:68-74`.
- **Naming vs categorizing is an EDGE distinction, not a NODE distinction.** "`/pizza` the folder and `#pizza` the label derive the same tagId… Placing a file at it is a PIN… labeling a file with it is a TAG." Splitting = namespace fork; squatting is inert because TAGDEF registration grants no privilege. `Reviews/2026-07-07-efsv2-corpus/kind-set-conservative.md:372-380`; ratified `Reviews/2026-07-07-efsv2-corpus/kinds-ruling.md:167-169`; app-grounding found no destructive folder/tag collision at the record level — "the confusion risk is UI vocabulary, not model" (`Reviews/2026-07-07-efsv2-corpus/app-grounding-consumer-apps.md:367`).
- **PIN and TAG stay two claim roles; "cardinality is part of slot identity."** `kinds-ruling.md:161-165, :286-288`.
- **TAG weight is kernel-neutral forever** ("effective TAG" thresholds are client policy). `kind-set-conservative.md:240`.
- **The query line**: one bounded cross-author enumeration + point reads; AND = enumerate rarest conjunct, hash-probe the rest via `getSlot`; **NOT declared gone on-chain**. `Reviews/2026-07-10-fs-pass-corpus/query-graph-boundary.md:10-25, :69-124`; disposition table `Designs/efsv2/fs-pass-synthesis.md:54`.
- **Target-keyed backlink index REQUIRED**, not optional. `onchain-graph-queries.md:51-61`; `fs-pass-synthesis.md:55`.
- **Advisory/deny claims are ordinary TAGs**; because the TAG slot key is `(author, definitionId, targetId)`, "does advisory author d advise against X" is a derivable point read. `Designs/efsv2/read-lens-spec.md:224`.
- **Name shadowing across kinds** has a frozen precedence order per serving context. `read-lens-spec.md:275-285`.

## 4. Tag assertions ("file X has tag T"): storage, indexing, negatives, expansion, joins

**v1 (shipped).** TAG attestation; on-chain `_targetsByDef`, `_edgeDefinitions[target]`, `_activeCount` (`onchain-graph-queries.md:32-34`); directory listing filtered on-chain by exclude TAG concepts + `minWeights`, union over viewed lenses, opt-in only (`sdk-architecture.md:441`). Negatives: ADR-0042 weight<0 suppression only inside manual filters (`Reviews/2026-06-10-holistic-review.md:264`). No AND, no implication expansion.

**July v2.** TAG claim body `(definitionId, targetKind, targetId, defParentId, defKeyHash, expiresAt, int256 weight)` 224 B (`kinds-ruling.md:27`); slot `(author, definitionId, targetId)`, re-assert = in-place update, revoke = swap-and-pop (`kind-set-conservative.md:239-241`). Indexes: per-tagId `discover(tagId, cursor, ≤256)` (P12, **still pending James**: `read-lens-spec.md:47, :448-451, :557`) plus target-keyed `discoverByTarget` (required). Postings word `author(160)‖spineIdx(64)‖flags(32)` ≈27k gas/append ESTIMATED (`query-graph-boundary.md:117`). **AND**: enumerate rarest + `getSlot` probes; SDK defaults k≤4, ≤1,024 driving entries, lens ≤8 authors; worked example ≈4.2M gas in one `eth_call` (`:107, :301`). **NOT**: "declared gone on-chain" — open-world, non-monotone; indexer-lane only, as-of labelled (`:121-124`). **OR**: client-side union. **Implication expansion**: not addressed. Cross-author satisfaction of conjuncts is legal (`:66`).

**Stage A B0.** A `TopicTag/1`/`TagAssertion` leaf touches the mandatory families: `KIND_TARGET` general backlink + `KIND_ROLE` predicate backlink per reference (`b0-indexes.md:900-921`); point probe = `KIND_BY_RECORD` page for a *known* RecordId at a basis (`:405-420`); compound keys **rejected for B0** (`:1077-1079`). First-order arithmetic nobody in media ran: ≈174k/leaf, p50 35-tag post ≈6.1M, p95 100-tag post ≈17.4M > EIP-7825 cap and > 64 leaves → multi-transaction post; 10k seed ≈7×10¹⁰ gas; under EIP-8037 ≈630k/leaf (`Reviews/2026-09-02-efs2-coherence-review-corpus/seams/S3-media-x-types-x-indexes.md:68-80`, all HYPOTHESIS-derived). An unexplored lever: one `TagSet` Record per post with ≤16 REFs ≈550k vs ≈2.8M, at the cost of the per-(post,tag) point probe (`:80`).

**Bitmap position (2026-09-10).** Index keyed `(scope(principal, DIRECTORY, D), tagId)` over the directory-local ordinal; membership 2 SLOADs ≈4,300 cold; positive scan `2,100·W`; **NOT = `alive & ~tag` within a listing, `4,200·W`** (256× better than per-file anti-join); AND `4,200·W`; Lens of k principals reads k words; open attester sets: no on-chain answer; index keyed on the binding position, never the record id; "images" vs "image/png" prefix needs a second posting at write (`indexing-and-state-2026-09-10.md:57-83, :124-187`). Write today ≈20–32k over the scope append; ≈50–75k under Glamsterdam (ESTIMATED, `:131-141`). Tag *record* today = 2,838,264 gas / 94 slots MEASURED (`gas-engineering-2026-09-10.md:30-34`); the Codex report gives 3,060,354 / ~133 slots for "tag" on a different run (`report-for-codex-2026-09-10.md:145-149`) — two figures, neither reconciled.

**Files-browser MVP fixture.** TAG = assertion leaf + Binding at `(object, tagId)` under `tagPurpose`; UNTAG = tombstone; "A's untag preserves B's" (`acceptance.md:23`); filters are positive-only over loaded rows, "no negative filters" (`:24`). ## 6. How far the vault is from an implementable tag design

Far, and the distance is structural, not polish. The vault holds one genuinely adversarially-tested tag model — the July tag-core (one derived, hierarchical, unowned TAGDEF namespace where a folder and a label are the same id; TAG = weighted, revocable, per-author cardinality-N claim; NOT off-chain; AND by rarest-enumerate-plus-probe) — and that model exactly encodes the owner's v1 intuition that `/clouds/nimbus` is both a path and a tag under a `clouds` grouper. But the 2026-08-12 greenfield reset demoted it to evidence, the active Files spine explicitly supersedes path-derived TAGDEF identity and says only "a tag is a many-valued relationship Record," and the three live successors disagree with it and with each other on the most basic question — tag identity is a kind-worded path segment (July), a kind-less path segment (efs15), a flat `Topic/1{name}` Record (Stage A), an unformulated namespace-scoped `TagConcept` (booru), or `keccak(tagString)` (the 2026-09-10 costing). No document anywhere specifies the record shape for a tag alias, a tag implication, a parent/child relation between two tags (outside the retired derivation), or a tag label/translation; "vocabulary version" is used but never defined; the booru set's own atomic object has two incompatible shapes; and the only tag write that exists in code costs 2.84M–3.06M gas on today's schedule and ≈11M under Glamsterdam. What *is* settled and reusable across every generation: tags are attributed per principal and resolved through a Lens, never global truth; tag metadata is separate supersedable records, never edits to identity; negation is only legal inside a closed listing; and the mission requires the postings/backlink indexes to live on-chain. A design that could be implemented needs, in order: one identity formula (and a decision on whether hierarchy lives in the id), one assertion shape (current-binding vs immutable-occurrence, ASSERT/DENY separation), the alias/implication/label record shapes with their expansion bound, and a measured per-tag write under both gas schedules — none of which any document currently owns.
