# EFS 2.1 compact native experiment implementation plan

> Experimental implementation authorized by James, September 11. Not an adopted replacement for v2. Canonical coordination: `Reviews/2026-09-11-efs21-overnight.md` on planning/main. Work from the isolated `planning-efs21` worktree; never modify the running Fable demo.

Goal: find a substantially cheaper practical contract filesystem while measuring, not hiding, the cost of retained guarantees. Architecture: immutable typed records and stable file/revision state in a compact kernel; separate-storage mandatory namespace navigation index; explicit optional-discovery coverage in a subsequent slice. No delegatecall or generalized journal duplication in this candidate. Native authenticated callers only in the first slice.

### Task 1: Compact native kernel, mandatory index and contract interoperability

Own only `Reviews/2026-09-11-efs21-pragmatic/contracts/`, plus a short `contracts-interface.md` in this experiment folder. Do not touch existing C0 contracts, control tests, SDK or browser. Use Solidity 0.8.30, Cancun, optimizer/viaIR as needed, no external Forge library dependency. Use test-first development with retained failing/passing command evidence.

Implement these focused components (names may vary; document final API for next task):

- `NativeKernel.sol`: immutable typed record bytes addressed by a domain-separated hash of exact TypeId and body; deterministic IDs independent of deployment/chain for records. Caller-authenticated namespace ownership; no tx.origin and no arbitrary author parameter. Stable file IDs distinct from location and immutable content. Preserve immutable revision history through edits/rename/unlink. CAS expected revision on updates/removal/move. A bounded body limit is an explicit experimental limit, not a Type-language ruling. Names reject slash, empty, dot/dotdot; bounded UTF-8 byte strings are fine without pretending Unicode normalization. Root directory per caller; nested directories must exist and be directories in the same namespace. Prevent directory cycles; either support bounded directory moves with a tested bound or explicitly reject moving directories in this slice. Removing nonempty directories rejects.
- `NavigationIndex.sol`: a genuinely separate deployed contract with its own storage and kernel-only mutation. Required current directory listing, per-caller file inventory and by-Type record inventory. It may store name bytes and live membership metadata rather than duplicate them in kernel. The kernel must expose exact point reads/path resolution, and bounded bulk listing should be usable by other contracts. Historical iteration and live iteration are distinct. If swap-and-pop is used for live lists, cursors must bind to a mutation revision and reject stale continuation; never silently skip/duplicate while claiming completeness. Mandatory index failure must revert kernel effects atomically. No arbitrary caller can replace the index or turn off required maintenance.
- `ExactTypeRegistry.sol` or a small kernel-contained equivalent: exact TypeId commits schema/validator identity; developer validation executes through a bounded STATICCALL before acceptance. Support a concrete uint256 validator and a bytes/text validator with correct malformed-data rejection. Pin runtime code hash, reject missing/changed validator code. Code hash alone does not freeze a proxy or its external dependencies: support reviewed stateless validators in this slice, and document that limitation instead of claiming arbitrary mutable callbacks are immutable. Validation revert/false/gas exhaustion rejects atomically. No permissioned registry needed for registration; avoid owner-controlled type reinterpretation.
- `Examples.sol`: a producer contract creates a swaps directory and writes an ABI-encoded quote/value into `eth-usdc`; an unrelated reader contract resolves the producer namespace/path and reads/decodes the value. Native publisher must be the producer contract, not the EOA calling it. Repeated publish updates the stable file and its revision, not a newly allocated file each time.

Keep interfaces compact and explicit. Deployment may use a kernel constructor that deploys its mandatory index for this fresh-genesis candidate, provided runtime state is genuinely in the index contract; code-cache CREATE from delegatecall context is prohibited. No upgrade mechanism required in this first slice; label this gap relative to the populated upgrade control.

Tests must cover: create directory/file; native producer-consumer initial/update flow; authorization/isolation between callers; stale CAS; stable IDs/history across rename/edit/unlink; identical typed bytes deduplicate and different TypeIds do not; invalid validator responses and callback/reentrancy attempt; unauthorized index mutation; forced index failure causing atomic rollback; nested path lookup, missing versus empty directory, nonempty removal, name conflicts; live page continuation and stale cursor; no silent present-after-unlink. Include a bounded fuzz/property test of record identity or revision history. Do not introduce huge traces or Anvil runs: Forge unit tests suffice here. Emit a reproducible gas report for named complete public operations but do not equate Forge test gas to final receipt gas.

Before coding, inspect local AGENTS.md and the relevant existing Files profile/design authority needed to understand stable file versus placement. Do not copy the entire C0 planner. Report decisions requiring semantic tradeoffs. Focus on a working, reviewed cost-control experiment, not a new production framework. Commit exact owned paths only with `Agent: v2-pm` and `Harness: codex` trailers. No subagents. Report tests, TDD evidence, API, limitations and commit in the controller-provided report file.

### Task 3: Optional discovery and lifecycle adversarial pass

After Task 1/2 review, choose a small separate Type-configured tag or scalar index with owner/developer cost authority, explicit required versus tolerated failure policy, bounded late backfill, and coverage qualification. Compare optional versus mandatory costs. Exercise old records, duplicates, edits/unlinks during backfill, replayed ranges, failed hook and recovery. Use an actual exact declared universe; do not substitute current placed files for admitted occurrences without naming the difference. The controller will refine interfaces before dispatch based on measured results.

Independent review recommends a first finite shape: `UINT256_EQ` over **current linked non-directory files** of exact Type T in one native namespace. This is explicitly not the C0 family7/9 occurrence universe. Namespace owner selects one profile and required/tolerated policy, because its writes bear the cost; unrelated registrants cannot tax that namespace. Index contract owns configuration and coverage; kernel supplies authenticated mutation notification. The architecture seam and changed-file ownership must be written before dispatch, not improvised inside implementation.

Use all-created namespace file ordinals as the stable backfill source universe (includes root/unlinked positions, filtered by exact eligibility). Attach pins high-water N. Bounded backfill covers [0,N), reading current state; subsequent creates above N and edits/unlinks anywhere are maintained by the hook. Retain per-file indexed bucket/presence so replays and edit-before-backfill are idempotent. Two files sharing bytes remain separate results. Initial implementation may use per-value live member arrays and FileId-keyed positions, with checked mutation-generation cursors. This avoids adding a mandatory reverse FileId-to-source-ordinal slot merely for optional bitmap maintenance. Stable ordinal bitmaps remain a later measured alternative, not a frozen requirement. Query cursor commits namespace/profile epoch/value/source observation generation. Even an observed member is not authoritative once a tolerated maintenance failure occurs.

Required hook failure reverts the full kernel/index operation. Tolerated failure first invalidates the entire profile coverage in the same transaction; all positive/negative/full-result claims become unavailable until a fresh epoch rebuild completes. Merely continuing the old frontier is not repair. Hook gas, return-copy and callback behavior are bounded. Initial simple maximum is one optional profile per namespace, labelled experimental. Test late attachment, duplicate content across files, cross-value and cross-Type edits before/after backfill, pre-backfill unlink, retry, new-file interleaving, malformed hook output/failure, rebuild, and stale/foreign cursors. Measure both write premium and read benefit.

Failure handling refinement: one immutable trusted discovery coordinator owns configuration, coverage and membership. The kernel's call to that coordinator is always fail-closed. The coordinator invokes bounded maintenance in a child call frame (`onlySelf` trampoline is sufficient for this exact scalar profile), catches a maintenance failure and persists DIRTY in its still-successful outer frame. If the coordinator itself fails or cannot persist health, the entire kernel write reverts. Do not attempt a second invalidation callback to the same failing contract. No arbitrary worker is necessary here, and a worker returning a dishonest success is not made safe by try/catch. Test the distinction between caught maintenance failure and uncaught coordinator failure explicitly.

### Task 4: Full-control optimization and decision report

The next full-C0 arm should first isolate physical separation: preserve all ten posting families, packed ordering/live counts, journal order, public APIs and all mirrors. Add a separate-storage kernel-only PostingStore with fixed-width head/word/keyAt reads and prestate-checked apply. Redirect StateStore.read/replay and the two StateReadPrimitives posting accesses; keep occurrence hydration in Core. Update raw accessors and corruption harnesses too. External apply owns its prestate check so Core need not fetch the same prestate twice. Keep vacated mappings as layout placeholders; do not claim populated migration.

Fresh paired deployment only: deploy the existing coordinator first, predict its Core at nonce1 and Carrier at nonce2, then have the **external runner/EOA** deploy PostingStore(predictedCore). The coordinator must not create the store and consume one of those nonces. Deploy implementations afterward, bind the adapter before StateKernel.initialize, then let deployPair perform its original two CREATEs. Avoid CREATE from Core delegatecall context and existing ProxyAdmin nonce collisions. Store owner may be a counterfactual nonzero address at construction; verify the deployed pairing before activation.

Keep the 21-word/672-byte ExecutionSet and executionId formula unchanged. Wrap only the legacy coreConfiguration in a domain-separated hash committing store address, pinned runtime hash and Core owner. Pin this binding once in the coordinator, reuse on upgrades, and independently calculate the same wrapper in candidate JS qualification readers; old readers should reject the new profile rather than trust an unexplained getter. Carrier configuration remains unchanged. No independent index generation is needed for this immutable always-on atomic parity arm. Compile-size gate first: the present admission library is already very near EIP-170.

Before savings changes, compare rows, posting heads/words/keys, duplicate occurrences, all-withdrawn/revival, current and noncurrent Binding withdrawals, same-key multi-leaf changes, history and Lens outcomes. Inject external index failure after kernel writes and later kernel failure after index writes; both accounts/nonces must roll back. Measure identical whole-operation receipts and contract reads. Expect extraction alone may cost MORE execution gas. Only then test word-batched reads, batched replay, counters or mirror reductions as separately named changes.

If time permits, independently measure counter/mirror removal with lifecycle equivalence, including lost per-record enumeration. Never conflate this arm with the compact candidate. Publish a concise main-visible gains/losses table and owner decisions. Review measured results and preserve the local demo/evidence for morning use. Final interface and file ownership are refined before dispatch, based on time and earlier evidence.

### Task 5: Stateless native priority Lens without write amplification

Independent review identifies a useful separate reader arm: `NATIVE_WHOLE_PATH_PRIORITY_V1`, not full Files overlay parity. Own a new stateless reader contract/tests and benchmark adapter; leave NativeKernel/NavigationIndex/write paths untouched. After a reviewed baseline, the controller can prioritize this small arm before broader optional index work if it yields clearer evidence for James.

Ordered distinct nonzero namespace owners (2–8), literal relative path segments and immutable kernel/codehash pin. Validate the complete input before early return. Resolve the whole path independently in each namespace, highest priority first. Only canonical absence permits fallthrough; a necessary failed/malformed read is UNKNOWN, and a non-directory prefix is blocked/unsupported, not absence. Stop after a higher confirmed winner; lower failures cannot invalidate a winner that does not depend on them. All absent yields qualified ABSENT_PROVEN. Return winner/provenance, record/file/revision, query commitment, chain/block number; offchain clients supply actual block hash. Never manufacture the current block hash onchain.

For readExact, select the winner first, then check regular-file state and exact Type and verify body identity. Wrong Type does not authorize lower-priority fallback. Keep path FOUND distinct from inability to materialize/read the selected content. Bound STATICCALL gas and returndata; exhaustion is UNKNOWN, not absence. No owner-contract callbacks; all reads target the pinned kernel.

Test winner first/last/all absent, reversed order, uninitialized versus empty roots, unlink revealing lower then recreate restoring higher with new ID, wrong Type/directory/prefix blockage, necessary higher failure versus irrelevant lower failure, malformed metadata/body hash/owner/live state, input/call budgets, literal percent/case, independent producer and consumer. Measure 2/4/8 namespaces and representative path depths/bodies. Publication gas must remain byte-for-byte unchanged because no write path changes.

Do not advertise merged complete directory listings, whiteouts, threshold/conflict voting, portable Principals, per-segment/shared-Object overlays, independent content-author plans or history-at-block from present state. Those require additional semantics. A complete merged listing cannot merely concatenate independently paged current directories; it must pin every relevant source basis and perform actual winner resolution.

### Task 6: Same-profile history storage compression

Only after Task2 has measured the unmodified aa6b1b6 contracts, investigate a separate fresh-genesis arm. The current public Revision repeats parent/name for every content edit. Keep its ABI and semantics, but internally store `StoredRevision(recordId,uint64 locationRevision,bool live)` plus immutable `locations[fileId][locationRevision] = {parent,name}`. Creation uses snapshot1; every move uses its new revision as snapshot key; edits/unlink reuse the prior pointer. Do not allocate a separate dense snapshot counter. `revisionAt` joins immutable rows, never the mutable navigation location. Retain old source/control and measure both arms; do not mutate any running deployment or silently load stale artifacts.

Preserve per-file CAS, validation on duplicate/same-content edits, one revision per existing operation, events, scope-generation changes, Type/Record identity, names, owner, all historical return bytes and all failures. Same-place moves remain operations. Test root/empty directory history, uint64 bounds, cross-file isolation, snapshot immutability and rollback on stale/auth/name/index failures. Differential sequences after every operation: create→many edits→rename→move→edit→unlink, same-value/same-place actions, name lengths1/31/32/33/64, zero uint256, empty logical bytes, Type changes, and bounded fuzz. Normalize deployment-qualified FileIds/cursors, not portable Type/Record IDs. Read ABI must remain unchanged so the same SDK/client operates either arm.

Hypothesis: edits avoid fresh parent/name words and long-name storage; create/move retain roughly the same data-word count with extra pointer/hash work; historical reads pay extra indirection. Measure actual receipts and read calls, runtime size and retained history, not estimated SSTORE savings alone. This is a stronger same-profile steady-write test than deleting functionality. Keep any independent hasRecord-Boolean removal separate: using nonempty body as presence depends on the current two-validator encoding restriction and must not become a hidden requirement on future EFS Types.

### Task 7: Payload representation and immutable byte-storage ablations

Do not assume Solidity's inner `abi.encode(bytes)` is required for a file's exact contents. The baseline 41-byte payload is currently a 128-byte typed body: offset/length/padding are stored as content in addition to the external-call ABI. A separate raw-byte Type could keep the same payload and file operations while changing its exact Type/Record identity and SDK decoding. It is a new explicit representation, not reinterpretation of existing records. It would validate arbitrary bytes, not promise UTF-8 or another schema. Retain the structured uint256 example unchanged. Test empty logical bytes, arbitrary binary, payload limits, exact byte identity and export; empty encoded bodies invalidate the earlier proposed nonempty-body presence sentinel, so retain explicit presence or prove a different safe encoding.

Measure this representation separately from Task6 and from a code-as-data body backend. For immutable code storage, include CREATE, code-deposit, pointer and read costs: small uint256 bodies may lose, larger bodies may win. Do not mix representation savings with state-storage savings or count omitted features as optimization. No numeric savings claimed until named receipt workloads run. Refine the implementation brief and source ownership before dispatch.

### Task 8: Generic ingestion versus Files profile boundary

The native candidate is deliberately filesystem-shaped, not yet a generic Core. A later extraction-only arm can move `_store`, `records/hasRecord`, `recordId/readRecord` and Type validation into GenericRecordStore; preserve the existing native public API as a FilesProfile facade for ownership, CAS, path, revisions and names. RequiredNavigation remains profile-owned; move generic `noteRecord/typeInventory` to a required record inventory with a forwarding getter if the old API must remain unchanged. Ordinary calls and EVM rollback preserve atomic required-index failures; this does not inherently require the old generalized journal. Measure added deployment/call/read overhead and preserve all existing differential outcomes. It is an architecture experiment, not promised gas savings or full generic Binding/Occurrence semantics.

Subsequent distinct acceptance/authorship arms should test the existing full structural Type evaluator behind a bounded ingestion seam, including nested types/references, malformed bytes, legal large schemas and developer predicates; then compact portable authored admission separate from permission to mutate a deployment. Test spoofing/replay/stale CAS/changed executor and rules, cross-deployment verification, and atomic required-index failure. Native FileIds remain deployment-qualified until a separately reviewed identity change. Do not call two-validator acceptance arbitrary programmability, and do not assume codehash freezes mutable validator dependencies. Scope each arm before dispatch; these are followups, not included in the current native savings claim.
