# The next useful MVP: cold names and qualified Files reads

September14. Consolidated bounded advice returned directly to the v2 PM by the
**EFS v2 SDK PM** and **EFS Data Explorer PM** after reviewing the paid Files
slice and withdrawal correction. This is a build recommendation, not adopted
SDK bytes, production authorization or proof that the old browser uses compact B.

## What the next vertical must earn

**A fresh guest must recover real filenames from public data.** The current
[[files-paid-results-20260914|paid Files slice]] stores hashed folder/name
placements; its fixture labels do not establish cold name recovery. Follow the
existing Files profile's exact Entry/name commitments or a clearly named
disposable equivalent. Do not use a warm browser cache, fixture map or hosted
index as the source of truth. This is an adapter/profile integration gap, not
evidence that Core needs a privileged filename primitive.

Run one small journey: **cold open, choose, remove, restore**.

1. A static guest with no wallet, account, indexer or cache opens an exact
   public folder link. Pin a block hash and recover/verify each exact path
   segment through the real Files/SDK read path. A labelled provider observation
   is acceptable for this MVP; a retained transcript is not a state proof.
2. Inject a missing name source and a corrupt one. Preserve their membership
   rows with `Name unavailable · <short key>` or an explicit integrity failure.
   Membership may be COMPLETE while name availability is PARTIAL. Do not drop
   rows, substitute friendly labels or claim a canonical name sort over unknown
   names. Files/SDK owns normalization; Explorer only renders safely.
3. Open F under Alice-first: show selected revision RA and Alice's selection
   provenance. Under Bob-first, show RB. File tag `project_efs` stays attached to
   F; RA tag `approved` does not leak onto RB. A conflict stays a conflict.
4. Move, reuse the old path for G, remove and atomically restore through the
   shared signing/reconciliation seam. Update the displayed result from canonical
   read-back. Say **Remove from this folder**, not delete all content/history.
   A higher mask must not fall through to Bob. Restore means a new revision RR
   using R0's bytes, not silently rewriting old history.
5. Inspect an occurrence withdrawal: retained selected contents, HEAD and tags
   remain readable. Zero active occurrences is neither deleted nor invalid nor
   “no maintainers.” Force scan-budget exhaustion separately: retain positive
   rows, show PARTIAL and continuation/direct-open, never complete-empty.

## Keep the SDK small and lossless

The SDK PM recommends three surfaces, with illustrative names only:

- **Qualified reads:** one `ReadContext` binds block, admission, index generation,
  rule epoch, Core/release and Lens. File results carry selected Record plus
  HEAD author/revision/admission; File-tag and selected-revision-tag assessments
  carry their exact subjects. Page values travel with coverage and continuation.
  The current disposable consumer drops some selection provenance that its
  tests check separately; an adapter can retain it without a new Core getter.
  Exact point reads need not depend on unrelated enumeration being COMPLETE.
- **Separate maintenance:** expose aggregate occurrence count and attributed
  withdrawal evidence separately from application validity, availability and
  selection. Policy-based validity needs its own evidence; the SDK cannot infer
  it from withdrawal or invent missing lifecycle information.
- **Queued writes:** prepare exact actions, bodies, author, nonce, expected HEAD
  and stable required-index obligation; authorize that digest once; submit it
  unchanged; reconcile canonical effects. Routine index progress may invalidate
  a cursor but must not silently rewrite a signed plan. Changed required
  configuration, nonce or CAS requires re-planning and fresh authorization.
  Native Solidity helpers must preserve the calling contract as author.

The [[index-obligation-config-finding-20260914|reviewed index repair]] protects
the lab's constructor-fixed required declarations; it does not manufacture
COMPLETE coverage. The [[files-withdrawal-reader-fix-plan-20260914|withdrawal
correction]] preserves retained reads, but does not add missing provenance fields
to the SDK or define every application's validity policy.

## Smallest honest product boundary

One public Realm, explicit Lens, bounded small-folder pages and exact path/ID
open; verified names/content, compact selection provenance and explicit tag
subjects. Staged move/remove/restore requires the shared signer seam. Withdrawal
can initially be inspection only. Large/churned folders remain bounded
PARTIAL/resumable until an actual live index is implemented and priced. The
[[live-placement-model-plan-20260914|algorithm model]] is not that index and is
not a bound in visible-file count. Cold-name recovery takes priority over
claiming a fast Finder replacement or polishing an ID-only debugger.
