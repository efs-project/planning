# Core closeout: recoverable Types and independent developers

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans.

**Goal:** An unrelated developer can define, validate, publish and independently interpret a new Type; additive reading and breaking changes have explicit behavior; copying meaning does not depend on the original publisher being online.

**Architecture:** One finite canonical descriptor profile, stored as recoverable immutable bytes, plus a mandatory stateless structural wrapper. Optional developer predicates remain mandatory inside that wrapper. Portable declaration authorization and local custom-instance installation are separate.

**Spec:** [[core-design-audit-20260915]], packet5; [[core-closeout-results-20260915]]. This is a disposable profile experiment, not the permanent schema language or protocol bytes.

## Global Constraints

- Existing compact lab, one source/build/chain worker; parent owns canonical documents and publication. No owner-demo changes, production scaffolding, public deployment, Fable, dependency installations or unbounded evidence.
- Existing exact Type/Record identity derivations and legacy opaque Types remain unchanged. New described identity commits exact recoverable descriptor, leading reference Types and fixed wrapper runtime. A URL, author label, compatibility assertion or hash with missing preimage is not an interpreter.
- Structural validation AND any declared custom predicate are mandatory on every publish/reuse. Realm policy may only add constraints. Preserve the existing shared300k mandatory-rule allowance, outer venue/code caps, ordered-prefix rules, final Files checks and whole-operation rollback.
- Permissionless registration does not grant mutable policy/placement administration, author data as someone else, overwrite an installed Type or authorize a same-code/different-state custom instance. Unknown or unsupported meaning remains explicit.

## Task 1: Finite described Types, mandatory custom validation and public registration

**Execution status September16:** complete and independently reviewed at prototype `cb4e8af`; exact evidence and qualifications in [[core-closeout-results-20260915#Finite described Types and public participation reviewed]]. Task2 remains separate; this is not a permanent schema-language or wallet-profile adoption.

**Files:** new focused descriptor/codec/rule files under `src/DescribedTypeProfile.sol` or a small explicit split; `src/TypeRegistry.sol`; narrow unknown-Type refusal in publication-profile calculation; focused tests and evidence under `core-closeout-types-20260915/`.

- [ ] Define one canonical finite descriptor with codec/profile version, declaration key/namespace, bounded retained semantic description, ordered stable field/semantic IDs, kinds/bounds, and optional custom ABI/runtime hash. References are the existing leading32-byte words; derive refs from the descriptor, not a conflicting second input. No self Type ID or destination address in the descriptor.
- [ ] First profile: up to16 fields/eight leading refs/4KiB descriptor and existing8KiB body. Support fixed refs/bytes32, bounded unsigned integers, canonical boolean/enum, bounded bytes/text and explicit optional presence. No recursive universal language, implicit coercion or automatic compatibility inference. Select and retain literal canonical vectors before implementing an independent decoder; unknown versions refuse. Measure maximum combinations rather than claiming all maxima fit300k.
- [ ] Leading checked REF fields are required; optional presence applies to non-reference fields. Reject optional-REF descriptors rather than shifting the fixed leading layout or treating zero as a valid absent reference. This is the finite experiment's explicit boundary, not an adopted permanent nullable-reference policy.
- [ ] Retain STOP-prefixed descriptor bytes in contract-readable immutable code. Verify their committed shape/preimage and Type/ref derivation. Opaque legacy registrations never acquire described interpretation merely because someone supplies a sidecar.
- [ ] Anyone may relay the original declaration signature over a versioned portable domain and exact derived Type ID. It excludes destination chain/registry/payer/address; signer must match the descriptor declaration key. Public custom-free registration selects only the fixed reviewed rule runtime. Duplicate identical relays are idempotent; conflicting immutable fields/bindings reject.
- [ ] Separate registration initialization from policy activation. New described Types get row1 at the existing policy epoch without bumping that epoch; track catalog progress separately. Admin policy/role changes still bump the epoch. Refuse PUBLISH/REUSE of an unregistered Type while computing its initial acceptance profile, so a callback cannot register a future leaf after an all-zero profile was signed.
- [ ] Mandatory wrapper is stateless, with no constructor immutables or arbitrary forwarding/delegatecall. Derive actual Ledger only from `msg.sender`; obtain its pinned registry through bounded getters; verify mandatory instance, wrapper code, descriptor, refs and complete shape. Only then invoke any declared custom predicate by bounded STATICCALL with explicit `(ledger,typeId,data,refs)` context and canonical boolean return.
- [ ] Custom predicate uses a new explicit-context ABI; legacy predicates retain their existing Ledger-caller ABI. Fixture authenticates wrapper runtime before trusting its forwarded Ledger, and checks creator-authorized `allowedLedger`. A direct forged callback and a fake Ledger calling the real wrapper cannot impersonate the genuine context.
- [ ] Descriptor commits custom runtime hash/ABI; local installation separately authorizes exact custom instance, allowed Ledger and binding context. For custom bindings, prefer one per-Type stateless wrapper deployed by registry CREATE2: salt commits the canonical local-binding preimage including chain/registry/Type/wrapper profile/custom instance/hash/allowed Ledger/authority. Its identical runtime preserves portable Type identity; existing acceptanceProfile's mandatory address commits local binding. Custom-free Types may share the registry's fixed reviewed wrapper because there is no hidden custom-instance/allowed-Ledger choice; enforce those custom binding fields are zero. No address/hash fixed point: custom runtime may pin wrapper runtime hash, never its future per-Type address.
- [ ] Installation is atomic; immutable binding cannot later be swapped or added. Retain declaration/binding preimages and signatures. Custom-free destination relay needs no new creator signature; custom-instance installation on another Realm needs its declared local authorization, not an assertion that identical code implies identical state. Descriptor retention/interpretation remains possible without that installation.
- [ ] Bound descriptor/binding/custom returndata before copying. Structure plus nested custom evaluation shares the existing300k outer allowance, including EIP-150 and return reserve. An always-true custom predicate cannot admit malformed structure; a rejecting custom predicate cannot be bypassed by permissive policy.
- [ ] Prove non-admin developer and separate relayer, same-code/state-different squatting refusal, wrong signature/context/code, unknown Type during callback, unchanged pending old-Type signature/continuation across unrelated registration, real policy change invalidation, and native/signed/duplicate/reuse/rollback behavior.
- [ ] Price descriptor/wrapper deployment and first/repeated registration separately from recurring reads/admissions. Per-Type identical runtime deployment is not free. If it is impractical, report the measured crossover and a small explicit local-binding-commitment extension to acceptanceProfile as the alternative; do not implement two routes or hide binding behind codehash.
- [ ] Preserve ordinary Node deployment and code caps; self-review, exact commit/report and independent task review.

## Task 2: Independent interpretation, evolution and source-off meaning

**Execution status September16:** active from reviewed `cb4e8af`. The controller supplies an additional previously unseen measurement/card fixture only after the independent decoder's commit/hash is frozen. Existing literal vectors are public inputs; producer parser/fixture encoder reuse is not independence.

**Files:** independent `browser/described-type-reader.mjs` and focused tests/literal vectors; bounded descriptor accessor in the SDK; guarded archive sidecars; a bounded paid/source-off integration script. No UI polish.

- [ ] Freeze the independent decoder before supplying an unfamiliar third-party measurement/card Type. It must interpret arbitrary supported fields without an allowlist of fixture Type IDs/names or publisher code. Compare Solidity validation, literal canonical bytes, decoded fields and exact IDs; malformed/unsupported is not valid empty data.
- [ ] Fetch descriptor/body from actual contract state, then decode the retained sidecars after stopping source RPC/publisher. Deploy another independent Realm and relay the unchanged original custom-free declaration: same Type/Record IDs, different local admissions and rule-instance addresses. No new original-author assertion is needed to retain or interpret bytes.
- [ ] Exercise three exact described Note-like Types: text, additive optional title, and a breaking rich-text variant. An explicitly approved source-Type-to-text-view mapping lets the unchanged old display function render the additive variant with omitted-field disclosure. A v1-only exact allowlist still refuses an unapproved Type. Rich text requires an explicit adapter/loss disclosure.
- [ ] An adversarial successor with tighter constraints or new edit restrictions cannot self-authorize compatibility. Old writers refuse Types/restrictions they do not understand; reading a projection is not permission to emit an older body that drops constraints.
- [ ] Archive descriptor/declaration, wrapper runtime/initcode/address and local-binding preimage/auth, custom runtime where applicable; independently recompute Type/ref/CREATE2/hash joins. Add an interpretation-coverage axis separate from byte/identity closure. Missing sidecars are PARTIAL/opaque; unknown codec is UNSUPPORTED. Bound aggregate descriptors/code, not just bodies.
- [ ] Measure cold paid descriptor/body consumption, normal native/signed publish/reuse, archive size and one/many admissions amortization. Retain longest legacy Note domain checks rather than silently shrinking text limits to fit the generic interpreter.
- [ ] Focused existing authority/guarded/archive covering tests; exact commit/report and independent review. No claims of universal schema expressiveness, automatic compatibility, stateful-rule equivalence or permanent neutral governance.
