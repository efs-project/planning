# Paid known-Record consumer experiment

> Staged, not dispatched. Use `superpowers:subagent-driven-development` for one bounded implementation, independent review and root reproduction. This adds a disposable consumer/test runner, **not a Core API** or a claim of authenticated RPC results.

**Goal:** measure the cost of a contract consuming already-known immutable data through existing raw versus qualified Core APIs, with explicit integrity/membership checks and identical application effects.

**Architecture:** two modes of the same bounded consumer, using the same trusted chain/Core, expected Record/Type IDs and inventory ordinals. Raw mode calls `record`; qualified mode calls `getRecord`. Both check body commitment, committed counts and exact inventory mirrors. The narrower mode relies on a separately inspected, frozen deployment; it does not prove that an upgradeable Core is honest.

**Source/spec:** [[2026-09-12-efs21-onchain-known-record-preflight]]. Re-pin to the reviewed then-current full-C0 source after intervening physical work. No Solidity saving has been measured yet. Use the existing compiler/settings and ordinary bounds.

Independent implementation-plan review: **Approved** after explicit returned-Type equality, bounded ABI framing, mode-specific metadata limits and reached-stage observer corrections. No implementation or performance result is approved yet.

The comparison measures **total raw-versus-qualified acquisition cost under common consumer checks**, not the isolated cost of execution-context qualification. Their additional checks are not identical or strictly ordered: qualified mode checks initialization and actual Record/Type row ordinal validity; raw does not inspect the Type row. Raw mode checks returned Record ordinal equals the expected one, while qualified mode only checks its internal ordinal is in range and does not return it. A corrupted but in-range ordinal can distinguish them in that opposite direction. These are explicit trusted-deployment profiles, not interchangeable proofs.

A good result does not license an unqualified browser API or remove the need for proper path/Binding/Lens reads.
