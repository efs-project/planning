## Lane — EVM / security attacker

I red-teamed the kernel write path (publish/admit → verify → occurrence state → binding → indexes) against the SR-1..SR-12 seam pins, treating the pins as binding and only attacking chapter text where an SR pin does not already imply the repair, or where the pin itself is wrong.\n\nThe good news the attacker could not break: the one external call in the atomic write path (ERC-1271 `isValidSignature`) is a `view`→STATICCALL with a hard gas cap and 32-byte returndata copy (principal §3.4), so reentrancy-to-write, gas bombs, and returndata bombs are structurally blocked and are already golden-vectored (GV-5/GV-10). The chain-free envelope domain relocates replay defense correctly into the Realm-bound intent (chainId+verifyingContract+realmId), 2-D nonces, and notAfter; cross-Realm/CREATE2 intent replay is closed. leafMask width and bits≥count, the U48/U32 guards, and the bounded posting/scan/candidate loops all hold. (1) The authorship↔authority seam is incoherent: Lane 3's verifier takes an `AccountPrincipal` struct, but the envelope wire and admit() ABI carry only `bytes32 principalId` and the authorship/realm call sites pass bytes32 — so there is no calldata channel for the P-256/RSA/contract public key (making those day-one authors unimplementable), and nothing binds the verified account to the declared principalId (a latent authorship-forgery hole). The log word is ordinal-indexed and exists only for ACCEPTED occurrences (indexes §2.2 `logSlotB(ord)`; ordinal assigned only on acceptance). ### [BLOCKING] selectBestLocator's loop bounds only LIVE candidates, so a spray of dead (self-revoked) postings at a target key makes the read cost O(dead history) — unbounded, violating the chapter's own acceptance rule (THE LINE), and the ABI has no cursor to resume from.

- **Evidence:** VERIFIED. ### [SERIOUS] The SR-10 pin itself narrows typeOrd/principalOrd from the index chapter's u48 to u32 with no exhaustion analysis; by the doc set's own uint32-rejection arithmetic, 2^32 local Principal ordinals is an exhaustible resource under permissionless Sybil-free Principal minting, and the narrowing buys nothing because u48 fits the word.

- **Evidence:** VERIFIED quotes; derivation shown.
