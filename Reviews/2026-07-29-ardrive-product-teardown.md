## What this is

The first product-layer study of ArDrive: onboarding, pricing UX, file management, sharing, privacy ceremonies, publishing, takedown policy, platform strategy, complaint signal, and company momentum — plus the surrounding field (mainstream drives as the expectation baseline, the dweb-drive graveyard, and the Arweave ecosystem's OS vacuum). Sources are primary wherever possible: the live app, the shipped Flutter string catalog, production payment APIs, release notes, archived help-center pages, and dated third-party coverage. Every lane report flags what it could not verify.

**Layer discipline (the mistake this pass exists to correct):** *Arweave* is the permanent-storage chain — EFS treats it as a byte carrier, and `ar://` is already a valid EFS mirror; a complement, not a competitor. *ArFS* is the filesystem protocol on top. *ArDrive* is the shipped product — web app, CLI, SDKs — and the thing that competes with our File Browser. This record is about the third layer.

## Verdict in one paragraph

ArDrive is a competently maintained, genuinely honest, strategically abandoned product. It proved the core demand ("a file manager over permanent storage"), proved the funnel (first permanent file in 3–6 minutes at $0, card top-ups, no tokens), and proved that mutable file UX over immutable storage works (rename/move/version/hide as cheap metadata revisions). It also spent six years demonstrating every failure mode EFS must design out: chain physics leaking into the UI, sync-before-browse architecture, an unrecoverable password placed at signup, irrevocable key-in-link sharing, a 35% fee the marketing page denies, permanent bytes behind rotting app links and dead help domains, and a naming layer now on its third execution layer in four years. Its user base is tiny (~1,500 protocol MAU as of late 2025), its parent company has pivoted to AI-provenance infrastructure, and its token is down ~97%. **As a competitor it is a maintained demo; as a syllabus it is the best one available.**

## The product, briefly

- **Clients (2026):** one actively developed Flutter web app (app.ardrive.io, weekly-ish releases; the repo's version bump to v2.86.0 was committed the day of this research — corpus: `live-probe.md`) plus a slow-cadence power-user CLI and two SDKs. Desktop died in alpha (2021), the Android app was sunset October 2025 with 39 lifetime ratings, iOS never shipped — Apple rejected pay-per-upload storage for bypassing In-App Purchase and ArDrive lost the appeal. Official mobile answer: PWA, or the Wander wallet's in-app browser. There has **never** been two-way folder sync. (Corpus: `platforms.md`.)
- **Account:** an Arweave wallet, full stop — in-app creation (seed + keyfile), seed/keyfile import, or extension wallets (Wander; MetaMask and Phantom/Solflare via deterministic Arweave-wallet derivation from an ETH/SOL signature). No email, no custodial tier, no recovery. A session password doubles as private-drive key entropy and **can never be changed or recovered** once a private drive exists. (Corpus: `sharing-accounts.md`, `private-drives.md`.)
- **Drive model:** wallet → many named drives (public or private at creation, private default) → folders → files. Foreign drives attach by ID/link into a "Shared Drives" sidebar section — but attach state is device-local and does not roam. Versioning is automatic on same-name upload under a stable File-Id, with history in an Activity tab; there is no restore button. "Delete" does not exist; "Hide" is an on-chain revision that can cost money and, on public drives, leaves the bytes publicly fetchable. (Corpus: `core-ux.md`.)
- **Payments:** Turbo credits via Stripe ($5 min) or 8+ tokens; credits pegged to storage purchasing power; uploads under 100 KiB free (now capped by a silent 10 MiB lifetime pool per wallet *and per IP*). Live price 2026-07-29: **$29.69/GiB all-in**, of which ~35% is a "Turbo Infrastructure Fee" itemized nowhere in the app — the marketing page says "no additional fees." Credits expire after 12 months per the current ToS (older material said 3 years; in-app copy still implies no expiry). (Corpus: `pricing.md`.)

## Journey teardown

### Onboarding — the best funnel in web3 storage, with a landmine at step two

A clean-browser user reaches a permanently stored file in **~3–6 minutes at $0**: wallet generated in-app, sub-100 KiB uploads free, drive/folder metadata transactions free ("Cost: 0 AR — free thanks to Turbo"), card top-up from $5 for everything else. Wallet education copy is genuinely good plain English. The hazards: the unchangeable, unrecoverable password is set at signup — before the user knows what a private drive is — with one sentence of warning and no strength meter; the seed backup ceremony was downgraded from a 4-word verification quiz (2023) to a self-attestation checkbox; "Sign Up" lands on a screen titled "Sign in"; and extension wallet options render only when the extension is already installed, which produced documented user confusion. Second-device recovery is the architecture's hero moment — import a seed anywhere and "We found your drives!" — but it ran on a 130-GraphQL-call, 376-second no-change sync until **July 2026**. (Corpus: `onboarding.md`.)

### Core file management — a 2008-era file browser with a great provenance story

Validated patterns worth copying: automatic versioning, metadata-cheap rename/move, the Activity tab as a free audit log, pre-mutation cost confirmation. The pain: a three-color status dot whose red state shows **documented false failures** during gateway unbundling (their own help says it "will be reworked for clarity"); "Drive Not Synced" gates; a paid **Snapshot** feature users are nudged to buy so their own drives list faster; a "Ghost Folder Fixer" repair tool; drag-and-drop that works for files but not folders; no keyboard shortcuts; name-only search that shipped in year four and only sees synced local state; no version restore; and a 65 GiB upload ceiling paired with a **download ceiling (500 MiB on Chrome per current code)** that the app UI never explains — and that the one live help page contradicts with different numbers (see Conflicts). The app ingests files it cannot give back through its own UI. The documented remediation path for a red dot is checking the TX on a block explorer and logging out to flush the cache. (Corpus: `core-ux.md`, `complaints-momentum.md`.)

### Sharing and permissions — capability URLs, and nothing else

Public items share as app links; private items embed the raw AES key in the URL fragment (never sent to the server — a sensible touch the product never explains). Recipients need no account: the shared-file page (preview, download, license, owner identity with ArNS name and avatar resolution; ENS/SNS names resolve on the profile/login surfaces) is better than almost any web3 app ships. That is the entire model: **no folder sharing** (since launch), no revocation or expiry ("they will have access to the file forever" — the promised link-spread controls from 2023 never shipped), no roles, no teams, no multi-user write of any kind (the request is the second-oldest feature request in the repo, filed August 2020, closed unshipped), and "shared with me" is device-local state that dies with the browser profile. A shared *drive* key silently includes all future uploads. The one real delegation primitive in the stack is Turbo credit spend-approvals — payment-side, not data-side. (Corpus: `sharing-accounts.md`.)

### Private drives — invisible encryption, no recovery, no erasure

Day-to-day private UX is genuinely good: one unlock per session, client-side-decrypted thumbnails and previews, private-by-default drive creation. Everything around it is a policy trap: one master password for session *and* all drive keys, frozen forever at first private drive; a per-drive-password retrofit (which also fixes drive keys persisting after logout) unmerged for 10+ months; **three ways to lose everything** — lose the password, lose the wallet, or have your wallet vendor deprecate a signing API, which actually happened (Wander's `signature()` deprecation forced an on-chain re-key ceremony on every private-drive owner, deadline open-ended). Because keys are deterministically re-derivable, ArDrive cannot even offer key-destruction-as-erasure. Marketing says "Total Privacy Control"; nothing user-facing mentions the permanent public metadata surface (payer wallet, timestamps, ciphertext sizes, revision cadence) or that "hide" itself leaves a permanent on-chain trace (public on public drives; an encrypted but visible revision event on private ones). (Corpus: `private-drives.md`.)

### Publishing — the folder→website primitive exists; the flow ends in a TX-ID scavenger hunt

Manifests turn a public folder into a served website in ~4 GUI clicks — real, shipped, and almost unique. Then the official guide tells the user to find the "Data TX ID" and hand-assemble a gateway URL. GUI updates mean re-creating the manifest and repointing the name every time; only the CLI (`permaweb-deploy`) does the loop atomically with dedupe. The naming layer is the strategic scandal: **ArNS migrated from SmartWeave to AO (2024) to Solana (2026)** — three execution layers in four years for the pointer system under "permanent" websites, with registration windows and claim deadlines that can strand name owners, and the $ARIO token it is priced in has collapsed to a ~$0.8M market cap. The genuinely excellent idea underneath: immutable deploys + one mutable pointer + undername staging channels (`staging_myapp`) + every historical version permanently addressable. (Corpus: `publishing.md`.)

## Takedown reality — who can make a public file disappear?

The question "if a government wants a public file taken down, can they do it?" has a layered answer, and ArDrive/AR.IO is unusually honest about it (corpus: `takedown-decentralization.md`):

- **Delete from Arweave: no one can.** The ToS says it in capitals: "WE HAVE NO ABILITY TO DELETE FILES… YOUR UPLOADING… SHALL BE PERMANENT." The protocol's "content policy" mechanism (miners individually choosing what to store) has no coordination mechanism and no documented case of purging a specific file network-wide.
- **Make it unreachable in practice: yes, routinely.** Takedowns operate at the gateway/index layer. arweave.net (run by the ar.io team) complies with DMCA by purging caches and blocklisting uploader wallets; every AR.IO gateway ships a per-operator blocklist admin API framed as a jurisdictional feature; the company delists content identifiers from its indexes and reports CSAM to NCMEC. A blocked file stays fetchable from non-blocking gateways or raw miners — but "fetch chunks from miners" has **no consumer tooling**, so for ~every real user, gateway blocking is effective removal.
- **Who can be compelled:** exactly the corporate surface — PDS Inc. (Delaware/NJ, DMCA agent) and each gateway operator in their own jurisdiction. Miners only individually. No court precedent forcing Arweave-level deletion was found in eight-plus years.
- **The documented real-world failure is over-blocking, not under-blocking:** one user's DMCA strike blocklisted a shared platform wallet and took innocent users' data offline with it; antivirus vendors flagging arweave.net broke NFT images for whole platforms. When it happens, the end user sees a missing file with zero explanation — there is no moderation transparency surface at all.

**Centralization map** (what dies with what): DATA is genuinely decentralized — it survives the company. ACCESS is semi-centralized (default gateway + a GraphQL index oligopoly of arweave.net + Goldsky; the AR.IO gateway network + Wayfinder client-side routing/verification is a credible, shipping mitigation). WRITES and PAYMENTS are a company product (Turbo bundler + custodial credit ledger; credits non-refundable, expiring, non-transferable). The app's front door is served via Google Firebase Hosting (verified first-hand twice: the repo's `firebase.json` deploy config and a live fetch of `app.ardrive.io/__/firebase/init.json` returning the active `ardrive-web` project — corpus: `live-probe.md`), though permaweb-deployed copies of every app version exist — their strongest single trust story.

## Momentum — how much of a competitor is this?

Corporate arc: Permanent Data Solutions (2020, $17.2M raised 2022) → AR.IO rebrand → ARIO token launch (Feb 2025) → token −97% to sub-$1M cap → protocol migration to Solana (2026) → homepage repositioned as "the verifiable data layer for the AI Era," with ArDrive demoted to a case study written in the past tense. Growth machinery dismantled: mobile sunset (Oct 2025, "haven't seen the level of usage and traction"), Zendesk help center deleted (dead DNS while still ranking in search), blog dead since ~2024, docs folded into AR.IO's developer portal, GitHub questions unanswered for months, a 3-review Product Hunt page (one review by the co-founder). Usage: ~1,500 protocol MAU (Nov 2025 ecosystem reporting), ~4,000 ArNS names, no ArDrive user counts ever published. Yet 2026 engineering is the strongest in two years — Solana login, cross-chain identity, the sync overhaul — because the app now serves the parent company's infrastructure strategy. **Threat level: low as a product competitor; high as prior art.** The lane is open: nobody owns "file manager over permanent/verifiable storage" with actual users. (Corpus: `complaints-momentum.md`.)

## The wider field

- **Mainstream baseline** (`mainstream-baseline.md`): the Tier-1 identity-defining set — folders with instant-feeling rename/move, drag-drop file+folder upload with progress, previews (images/PDF/streamed video/audio/text), ZIP folder download, filename search with filters, viewer/editor share links, trash with a stated window, responsive mobile, Recents — is the credibility floor; missing items read as "not a drive." Four expectations are structurally hostile to permanent storage and must be *reframed, never silently absent*: true delete, cheap implicit versioning, free-feeling writes, server-side content search. Proton Drive is the existence proof that users accept capability loss at a 2–4× price premium **when the product explains why at the moment of impact** and pushes recovery rails at onboarding. The pricing anchor everyone is compared against: ~$5/TB/month and falling.
- **The dweb-drive graveyard** (`dweb-alternatives.md`): the four killers, by body count — VC/token-subsidized free storage (Skiff, Skynet, Fleek, web3.storage/nft.storage), company-domain link rot (**siasky.net, the domain in every Skynet share link ever posted, is now a squatted gambling site**), payment/onboarding friction (Fairdrive: five years of commits, ~zero users), and permanence rigidity (Akord — ArDrive's only real Arweave competitor — exited to Walrus/Sui explicitly because a drive product needs delete and expiry). The survivors won by boring means: Internxt (~1M users, profitable) dropped decentralization and kept the privacy pitch with credit cards and lifetime plans; Pinata (600k devs) became a boring files API. The single best idea in the wreckage is **Akord Weave**: a read-only client the company committed to deploying on the storage layer itself, so vault access survives the company. Decentralization retains; it does not acquire.
- **The Arweave OS vacuum** (`os-ecosystem.md`): seven years of permanent storage + 1.5 years of AO compute + naming + a wallet produced **no OS** — no shell, no session model, no living app directory (best index last updated Apr 2025), retention loops that are token-farming rather than daily utility, and a wallet identity layer whose own brag numbers work out to ~5 lifetime transactions per install. The one OS-grade mechanism — immutable versioned app builds behind a mutable ArNS pointer with undername channels — never got a consumer surface (no version UI, no pinning, silent repointing). Composability emerged only where a first-party team shipped an SDK *and* a flagship app enforcing its schemas.

## Where ArDrive is genuinely better than anything we've designed

Named plainly, because a flattering-to-us report is a useless one:

1. **The $0-to-first-permanent-file funnel.** Free small writes + free metadata ops + $5 card top-up, no tokens, no KYC, no extension. We have gasless faucet-drip as a hackathon must-have; ArDrive has the whole funnel shipped and measured.
2. **Payment onboarding breadth.** Stripe fiat (190+ countries via the Turbo/Console rail; the ArDrive in-app dialog itself is USD-only), 8+ tokens across four chains with installed-wallet auto-detection, storage-power-pegged credits, email gifting (recipient needs no wallet — shipped, though possibly since walked back: the gift UI was removed in v2.82.0 and sources conflict on current status), and delegated spend approvals with caps/expiry/revocation. Nothing in our design set matches this today.
3. **Cross-chain identity resolution done right.** Deterministic Arweave-wallet derivation from an ETH/SOL signature; ArNS + ENS + SNS names with avatars on every owner surface. Their login screen meets users at the wallet they already have.
4. **The no-account recipient page.** Preview, download, license, resolved owner identity — zero login nag. Most web3 apps fail this; so would a naive EFS client.
5. **Permanence honesty copy.** "There is no delete button (for you or us)!" / "Think twice before uploading all your teenage love poetry…" — blunt, funny, repeated at the right moments. Best-in-category expectations-setting, matched by a ToS that says the same thing in capitals and a published COO article explaining exactly how takedowns work.
6. **Mutable UX over immutable storage, proven.** Rename/move/version/hide as cheap metadata revisions with stable file identity — shipped years before anyone else, and it works.
7. **Self-hosted app resilience.** Every web-app version permanently deployed to the permaweb with full version history — "if we disappear, the app and your data keep working" — plus a graceful product sunset playbook (the mobile FAQ: clear dates, keyfile export, APK archived on Arweave).
8. **Release hygiene.** Weekly-ish shipping with release notes that quantify their own past failures ("376 seconds → under 1"). Top-decile for web3.

## Where the room is

Condensed from the per-lane weaknesses; each is an opening the requirements doc converts into a differentiator:

- Chain physics in the user's face: false-failure status dots, sync gates, block-explorer remediation, paid snapshots to make your own drive listable.
- No permission model at all; irrevocable future-inclusive sharing; device-local "shared with me"; no folder sharing.
- The unrecoverable password; no re-key, no recovery ceremony, no erasure story; wallet-vendor API changes as an unmanaged threat model.
- Fee opacity (35% embedded; "no additional fees" marketing) and credit expiry buried in ToS while in-app copy implies the opposite.
- File-browser ergonomics circa 2008: no keyboard, no folder DnD, no filters, no restore, name-only search, 500 MiB download ceiling.
- Support-surface rot on a permanence product: dead help domain, dead gift domain, 404 announcement pages, unanswered issue tracker, domain sprawl confusing enough that "which site is official?" sits unanswered on GitHub.
- Naming/pointer layer on a migratory chain priced in a near-dead token.
- Accessibility zero: Flutter canvas rendering with an empty accessibility tree — screen readers are locked out; password managers and browser autofill are degraded.

## What EFS learns (the ten load-bearing lessons)

1. **The settlement gap is the product.** Design the pending lifecycle as first-class UI (our pending-state ladder + read grades are exactly this); never show a false failure; never ship a "deep sync" button or a block-explorer remediation path. ArDrive's decade of status-dot pain is the strongest validation of the honesty doctrine we already adopted.
2. **Never gate browsing on a full sync.** Stream/page listings from the index with a local cache as accelerator, never as gate. ArDrive monetized its own architecture failure (paid snapshots); our lens/checkpoint reads must make "open a big folder cold" a sub-second experience.
3. **Match the funnel bar: first file on chain in under 5 minutes, $0, clean browser.** And beat the two things they fumbled: a real backup ceremony (not a checkbox) and no unrecoverable secondary secret, ever.
4. **The canonical share artifact must be protocol-native.** Skynet's link graph rotting into a gambling site and ArDrive's own blog-era app links bouncing to a welcome screen are the same lesson at two severities: company-domain URLs and unversioned app-route grammars both rot. `web3://`-native links with labeled, disposable https mirrors; link grammar treated as an Etched-tier compatibility surface.
5. **Sharing needs revocation by design.** Capability URLs are the right transport; ArDrive proves that on immutable storage a leaked key is forever and that "don't paste it publicly" is not a mitigation. Our mutable on-chain layer can do what they structurally cannot: expiring grants, re-keying, per-item wrapped keys, and "shared with me" as roaming on-chain state. Folder sharing day one.
6. **Deletion needs an honest story, not silence.** Ship the trash-can affordance mapped to unlist/hide with Proton-grade copy at the moment of loss ("removed from your view; bytes already on permanent mirrors cannot be unpublished; hidden ≠ private — the hide event is public"). Per-mirror permanence differences (ar:// forever vs re-writable mirrors) surface per file.
7. **Make immutability the versioning headline and ship the restore button.** "Version history: forever" beats Dropbox's 365-day enterprise tier — with one-click restore-as-new-revision, which ArDrive never shipped despite having the model.
8. **Keep names, pointers, and payments on the filesystem's chain, and keep tokens out of the UI.** ArNS's three-chain migration and the ARIO/Turbo fee steering are the canonical failure; Ethereum-native pointers + ENS, with any service fees itemized at the commit point in fiat terms, are the counter-position.
9. **Fewer surfaces, kept excellent — and the OS must be first-party.** Four ArDrive clients contracted to one; the permaweb's primitives never self-assembled into an OS; composability happened only where a first-party SDK + flagship app enforced schemas. Files is our BazAR: the reference consumer of the platform, with every power it needs expressed as named grantable capabilities.
10. **Files must be the daily-return loop.** The permaweb's retention vacuum got filled by token farming. A file browser natively has the "changed since yesterday" property — shared-folder activity, incoming files, sync state, version events. Build that surface into v1; it is the retention mechanism and the reason the archive loop (save → organize → cite → share links that never rot) can win.

## Positioning line

For grant applications and the site (deliverable 3; one sentence, two available registers):

> **"EFS uses Arweave the way ArDrive uses it — as a permanent byte carrier — but where ArDrive is one company's drive app over one canonical tree, EFS is the filesystem itself: a shared, verifiable, on-chain namespace that every viewer resolves through their own trust, with no company in the read path."**

Short form: *"Arweave is a carrier we mirror to; ArDrive is a drive app we out-file-manage. EFS is the filesystem."*

## Conflicts and unverified claims (aggregate)

Carried forward from the lane reports' own flags; do not cite these as settled:

- **Credit expiry:** current ToS says 12 months; older help material said 3 years; in-app copy implies non-expiry. The ToS is presumptively authoritative; the history of the change is unverified.
- **Upload limits:** current code says 65 GiB hard cap (5 GiB soft warning); archived help (Jan 2024) said 65 GiB direct / 10 GiB Turbo with browser variations; stale in-app strings still say 1.20 GiB public / 100 MiB private; the live ardrive.io/help page says 2 GiB web. The code is presumptively authoritative for the web app; the strings/pages are rot.
- **Download limits:** current code (`download/limits.dart`) says 500 MiB Chrome / 2 GiB Firefox / 1 GiB Safari; the live ardrive.io/help App Limits page says 15 GiB web download (1 GiB Safari). Code presumptively authoritative for the web app; either way the ceiling is undocumented in the app UI itself.
- **Email gifting:** shipped 2023 (gift.ardrive.io + help article) and cited in Turbo/Console docs, but the gift UI was removed from the app in v2.82.0 (2026-06), gift.ardrive.io no longer resolves, and current docs language says gifting is "not currently possible." Treat as walked back; current status conflicted.
- **Turbo upload scanning:** no evidence of proactive CSAM/content scanning at ingest; ToS language suggests reactive-only. Probable but unconfirmed.
- **Gateway/miner decentralization figures:** AR.IO gateway counts range ~582 (network-portal snapshot) to ~600–700 (company homepage / ecosystem year-in-review); miner concentration <1% (single academic source) — all unverified independently; traffic share unpublished.
- **Reddit/Discord complaint volume:** inaccessible to this research; complaint-thinness conclusions rest on accessible channels plus the vendor's own troubleshooting taxonomy.
- **Wander install/transaction figures** are self-reported marketing numbers.
- My live probe's old-share-link failure was re-interpreted after code review: the current app does serve anonymous shared-file pages; the observed failure is a dead/unresolvable old link plus a silent bounce-to-welcome error UX — not a login wall.
