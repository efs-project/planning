## What the experiments changed about the real build

1. Keep kernel data admission, mandatory index callbacks and qualified read results separate. The historical-location defect is a concrete example of why index coverage and first observation belong in read meaning, not only in UI prose.
2. Keep Lists and homes above Core as exact application Types. The small profiles prove composition; they do not justify `LIST`, `HOME` or ENS-specific kernel nouns.
3. SDK reads should carry value, basis, coverage and unknowns together. The joined-page path was decoding a nested response twice; the prototype now reuses the validated decode once per caller while retaining raw-cache validation. A source-pinned fresh Node child completed 1,000 Files under the previous memory cap. The production SDK still needs a bounded cache/streaming policy and actual browser/public-provider measurement before promising that scale as an SLA.
4. Contract consumers need a small bounded page or exact point, not a promise to read an entire social/gallery collection in one transaction. The positive four-row page fits a local gas envelope; the full-gallery economic answer remains open.
5. Keep fresh-genesis profile changes in the prototype. Real-repo artifacts must version exact rule/index obligations and cold-recover their *actual* release build, not inherit lab Type IDs or assume old archive adapters.

The public Files Name decision is product-facing, not a reason to reopen Core. The current onchain-proven first profile is the restrictive 1–255-byte lowercase ASCII segment (`[a-z0-9._-]`, excluding `.` and `..`). The design's richer NFC/Unicode profile has strict source/table pinning and an explicit validation-grade boundary, but this lab has only cross-language scalar vectors—not a gas/size-qualified full onchain validator. Recommend starting the real repositories with the proven exact ASCII contract path and a versioned route to richer names; do **not** advertise arbitrary Unicode filenames or silently replace a user's name with a slug. Whether rich names must ship in the first public Files release is a visible M3/owner product choice.

## Readiness rule

The seeded local browser is ready for James's click-through at the currently running disposable workbench, but this is not a wallet/provider certification. The remaining **production** blockers are engineering/release work in M1–M6: module decomposition (the Ledger runtime is 24,524 of 24,576 allowed bytes), public profile selection, browser-scale memory behavior, real wallet/carrier UX, exact-build recovery, public-RPC/fee measurements and deployment authorization. None is a reason to rewrite the demonstrated exact-record + authored-binding foundation without a failing counterexample. The real repositories may be opened after owner environment approval while these interface limits remain explicit; public release may not be inferred from that permission.
