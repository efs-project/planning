## Constraints and explicit choices

- Code only in authorized full-C0 experiment worktree/branch; plans/results visible on main. One implementation/build/new finite-world owner. Preserve all three demos and Fable's workspace; no production repo, migration, public chain/funds or protocol freeze.
- Keep ordinary runtime24,576/initcode49,152/transaction16,777,216/block33,554,432 limits. No Type-language reduction, cache compression, Files-profile change, raw-reader redesign or global allocator. Stop heavy work below20GiB; managed watchdogs, exclusive outputs and exact owned cleanup, no traces.
- Keep all ten posting families, including already Type-selected7/9, and the posting-key mirror. Family3/counter replacement and family-removal economics are later tasks. Existing checked audit pages support8/10; do not claim every family has that API.
- Use a fresh-genesis **appended, write-once Store-address field** for delegated admission/query libraries. Reserve all old mapping roots and enum values; there is no zero-address fallback to abandoned mappings. This is one explicit configuration row/layout extension, not literally unchanged physical layout. Alternative explicit address threading is not bundled.
- Core implementations pin Store address/runtime hash. An existing21-word execution set can bind the added dependency through a domain-separated **Core configuration wrapper**; Carrier configuration and the execution-ID formula stay unchanged. Factory must retain the genesis Store tuple and refuse replacements during ordinary pair activation, not bless whatever a new implementation reports.
- Store is immutable, not a replaceable optional index. Its immutable writer is the Core proxy, not library/router/author/implementation/admin. No setter, callback, delegatecall, Core lookup during mutation or arbitrary row-write API.

## Why stage this separately

The native prototype already has mandatory and optional separate contracts, but its smaller authority/history model is not the full model. This experiment establishes the full model's physical separation first. Dropping universal per-Record occurrence lists, introducing counters, and late configurable-index declaration each have different inventory/coverage/withdrawal laws. They should be measured against this explicit boundary, not hidden in a broad rewrite.
