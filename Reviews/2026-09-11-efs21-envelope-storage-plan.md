## Result boundary

September12 source review found that the first results draft called actual Core reads an approved substitution for separately requested receipt-library pricing. That was inaccurate: the earlier ABI clarification had not waived that measurement. Root now narrows the economic gate explicitly to actual routed Core APIs and retains receipt-library correctness coverage, leaving scalar/repeated receipt-library paid gas unmeasured. A new unauthenticated harness would price a different context; no full paid-read coverage claim is allowed. **Cost of this ruling:** a receipt-library-specific gas regression remains outside the measured bound and needs a separate test before such an API is relied upon economically.

This is the smallest fuller-model immutable-byte experiment, not the full cost solution. It may save storage while adding creation/read overhead. A later shared Envelope+new-Record slab has a bounded10496-byte aggregate payload, but requires separate range, dedup, installation-order and failure-timing design. Separate posting storage/configuration and native data-model tradeoffs also remain distinct. No saving or full-v2 readiness is established by this plan.
