## 4. Q2 — Safari measurements and the Arcade slice

### 4.1 What the measurement says (`Reviews/2026-08-13-claude-evidence-round/corpus/runner/browser-runner-measurements.md`)

1. No process isolation for opaque sandboxed iframes in Safari: 3 s busy loop → 3027 ms host freeze; Chrome 51 ms (`:21`, `:150-164`).
2. ~22 rAF/s and ~34 timer ticks/s for any cross-origin child in Safari vs 60 for the host; "tracks cross-origin-ness, not sandboxing" (`:23`, `:173-185`).
3. Sandbox is not a no-egress boundary: fetch/no-cors, WebSocket, `<img>/<script>/<link>` all work; `Origin: null` (`:76-89`); self-navigation to any URL succeeds and "inherits the sandbox and the opaque origin" (`:91-108`).
4. `allow="fullscreen"` alone → disabled in Safari; legacy `allowfullscreen` alone → enabled; both → disabled (`:24`, `:137-148`).
5. Safari keeps a WebSocket open ~5.6 s after `iframe.remove()` (`:25`, `:187-195`). Firefox, iOS, Android, touch, gamepad unmeasured (`:205-225`).
The round README binds this as "useful runner evidence, not a chosen policy" (`Reviews/2026-08-13-claude-evidence-round/README.md:27-30`, `:132-155`) and `CORRECTIONS.md:24` warns the measurements are one machine, mostly n=1.

### 4.2 Does `app-runtime-and-direct-launch.md` integrate it?

**Partially by shape, never by citation.** Integrated in substance: "Sandboxing does not by itself block HTTP, WebSocket, subresources, WebRTC, self-navigation, renderer hangs" (`:644-648`); the epoch/nonce handshake because "its `WindowProxy` survives navigation" (`:634-642`); "Frame removal is best-effort browser teardown, not proof that the frame had a separate renderer/process or that a busy renderer could not temporarily stall the host" (`:707-710`); lane table residual "renderer DoS and Web bugs" (`:447`); fixture 10 probes "renderer starvation across Chromium, Firefox and Safari" (`:932-940`) and fixture 15 names "shared-process hang" (`:957-962`). **Absent:** the Safari process-isolation measurement itself, the ~22 fps throttle (nowhere in the set — grep of all web-client-os docs for `22`, `process isolation`, `browser-runner-measurements`, `2026-08-13`, `allowfullscreen` returns nothing except the generic "SES is not … process isolation" phrases), the fullscreen-attribute trap (the doc only says gesture-gated actions "use a runner profile fixed at construction and tested for that gesture", `:277-280`), and the WebSocket-after-removal lag. The doc's §Current primary evidence (`:1037-1089`) lists only external sources; the vault's own measured matrix is not among them, and the README's `Inputs` line names only historical `clientv2` docs. Safari appears twice, only as a future test target (`:935`, `:1109`). This is finding F3.

### 4.3 What it promises for the Arcade one-game slice, and whether Arcade says the same

Promised: "Arcade remains explicit Play even when its detail route is direct" (`:256`); the opaque full-Web lane with construction-time sandbox/CSP/Permissions-Policy and closure-backed resource URLs or an immutable virtual mount, "never Locators or partially verified members" (`:615-627`); first third-party App proof item 3 "one exact opaque full-Web App/Arcade fixture with honest direct-egress labeling" (`:859-868`); and the label law: a profile that can "fetch and interpret mutable instructions" is `MUTABLE_REMOTE_EXECUTION_OR_DATA`, "requires explicit Launch, and loses exact-execution, offline and reproducibility qualifications. Its exact authored Release remains provenance for the bootstrap closure; it is not a claim that the resulting behavior was fixed by that Release" (`:652-661`). `product-constitution-and-roadmap.md` Slice D restates it (`:285-295`); `mvp-and-acceptance.md:849` says "later prove corrupt-primary fallback and one opaque-frame profile".

`Designs/arcade/player-security-model.md` agrees on: explicit single Play gate (`:54`), verify-before-execute (`:58-73`), no wallet/EFS object in the frame (`:44`), shell-owned exit/restart outside game pixels (`:75-83`), egress not blocked and labelled (`:50`), and the invariant that hashing covers only the mounted document ("A sandboxed frame with open egress could still `<script src>`, `fetch`+eval…", `:112`). It **differs** on: (a) container = `srcDoc={verifiedBytes}` with a `<meta>` CSP explicitly rejected (`:39`, `:50`) versus the OS law's requirement for a measured CSP/resource-delivery profile before an exact-qualified label; (b) no nonce/epoch handshake or `MessagePort` at all; (c) tab-freeze "accepted at demo scope; curation gates entry" (`:31`) versus the OS's requirement that rescue after a shared-process hang be proven (fixture 15); (d) it still routes approval of the iframe lane to the historical `clientv2` kernel doc via PAF-5 ("**not decided here**", `:16`), whereas README direction #26 (`README.md:150-155`) and app-runtime have since made the opaque iframe the full-DOM lane; and (e) it is v1 `contracts/packages/nextjs` work, displaced by the 2026-08-08 greenfield ruling (`Decisions.md:23`) and the Arcade README's own "Client/OS placement and runner/network permissions remain open" (`Designs/arcade/README.md:20-22`). The net effect is finding F4 (label conflict on "exact execution") and F5 (stale routing of the lane decision).

## 7. Q5 — Internal contradictions

1. **Exact whole-system generations vs independently updatable modules (UNDECIDED, F2).** README's historical-audit row says "Split base, handler, system-profile, install, and session generations so unrelated modules need not update atomically" (`README.md:388`). `system-profiles` product law 10 says "One local coordinator tuple selects one coherent system graph.
