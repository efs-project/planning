## 1. Headline

The Arcade set is a well-argued 2026-08-07 v1/Sepolia launch plan (12–18 games, giscus comments, GitHub-PR curation, on-chain star via a faucet, 2026-09-11 ship date) over which a two-paragraph correction was laid on 2026-08-08/12/13: one game (Andromeda Invaders), no durable EFS write, a provisional adapter, EFS 2.0 Core as target, owner queue held. The correction is real and consistent across `README.md`, `Designs/README.md`, `Kanban.md`, `Open-Decisions.md`, and `Decisions.md` (2026-08-13), but the recut the README itself names as "the highest-leverage next action" (`Designs/arcade/README.md:44-46`) never happened: the last commit touching the folder is 2026-08-13, ten of twelve bodies still narrate the September plan, every September gate date has passed unmet, and no `/arcade` code exists in any repository. The set therefore has two layers that do not talk to each other: a current one-paragraph direction with no design under it, and a superseded design with no direction over it. The parts that are genuinely solid — explicit Play, verify-then-mount with locator fallback, the opaque `allow-scripts` frame with honest egress labels, the rights intake classes, the error taxonomy — are already restated by the current Core, App Store and Web Client docs as a *fixture* (`system-constitution.md:310`, Stage A `FX-ARC`, `open-web-app-store/architecture.md:914`, `app-runtime-and-direct-launch.md:862`). What the set does not have is an owner for client placement, an object vocabulary that matches those neighbours, any reflection of the 2026-08-13 Safari/mobile measurements, or an honest product case that survives its own falsification round.

### 4.2 Mismatches

1. **Ring-3 language and "MISSING at ruling level" are stale.** `player-security-model.md:16` frames the runner as "NOT a v2 Ring-3 app… The clientv2 kernel's 'no iframe-hosted app logic' rule… routed to [client-os-pressure-report]"; `v2-pressure-and-migration.md:40,:63-67` classifies the iframe runner as **MISSING** pending a ruling by the `[[kernel-capability-model]]` owner via PAF-5. The lane exists; the Arcade set still says nobody has approved it. "Ring-3" does not appear in the current web-client-os spine's lane vocabulary at all.

2. **"Verify-before-execute" vs "exact before execute".** The Arcade container is `srcDoc` with meta-CSP explicitly rejected and "Outbound network is NOT blocked" (`player-security-model.md:50`); its own post-review invariant admits the frame "could still `<script src>`, `fetch`+eval, or navigate itself to remote content — unverified code inclusion the hash check cannot see" (`:112`). Under the runtime law that profile is not an exact-qualified launch: "A profile that can acquire and execute mutable remote code is a separately labelled remote-code session" (`app-runtime:66-68`), it is `DIRECT_EGRESS` unless a measured CSP design exists (`:646-648`), and if the App can "fetch and interpret mutable instructions" the session is `MUTABLE_REMOTE_EXECUTION_OR_DATA` and "loses exact-execution, offline and reproducibility qualifications" (`:656-661`). The measurement confirms the mechanism: "The frame can navigate itself to any URL on the internet and stays sandboxed when it lands" (`browser-runner-measurements.md:27,:104-108`); `fetch(... no-cors)` to the public internet "works" and WebSocket is "fully functional, no CORS gate" (`:83,:86`). The security model's *control* for this is curation ("a game that loads any runtime subresource fails intake", `:112`) — a policy control, not a runtime one, which the runtime doc does not accept as a qualification. Also `srcdoc` is on the runtime doc's *unmeasured* list (`app-runtime:1022-1025`) and the doc requires "verified closure-backed resource URLs or an immutable virtual mount" (`:622-623`).

3. **Process isolation / hang residual is engine-specific and the set says "typically".** `player-security-model.md:31` (T5): "srcDoc frames typically share the parent renderer process — a hostile tight loop can hang the tab". Measured: Chrome puts the opaque sandboxed frame out-of-process and the host "never stutters (51 ms max gap)"; Safari freezes the host for 3.0 s (`browser-runner-measurements.md:21,:153-164`). The runtime doc states the honest version: "Frame removal is best-effort browser teardown, not proof that the frame had a separate renderer/process" (`app-runtime:707-710`). No Arcade doc records the split.

4. **Mobile / WebKit claims have no evidence in the set.** Safari runs an opaque/cross-origin child at "~22 fps while the host runs at 60" and "`allow=\"fullscreen\"` does not work in Safari, and actively breaks it" (`browser-runner-measurements.md:23-24,:176-185,:140-148`); iOS Safari, Chrome Android, real touch and gamepad are "entirely unmeasured" (`:208-216`). The set's mobile posture rests on `catalog-plan.md:23,:28` (touch bar; ≥40% touch), `rights-safety-and-operations.md:105` (12 of 15 keyboard-only), `september-plan.md:95` (acceptance 1: "fresh iOS Safari or Android Chrome visitor"), `unknowns:U5`, and README's "mobile-capable" target. None mentions the WebKit rAF throttle, which affects every action game on iOS (WebKit-only). The Andromeda memo tested "one browser tuple (Chromium-family desktop + emulated mobile)… No Safari/iOS WebKit or Firefox verification" (`andromeda-evidence-reproduction.md:107`). The runtime doc's fixture 10 requires the full-Web residual probe "across Chromium, Firefox and Safari" (`app-runtime:932-940`).

5. **Fullscreen.** `player-security-model.md:82` defers shell-owned fullscreen; the Safari attribute interaction (legacy `allowfullscreen` works; `allow="fullscreen"` disables; both → disabled, `browser-runner-measurements.md:24,:148`) is exactly the kind of construction-policy detail the runtime doc says must be "fixed before construction" (`app-runtime:620-621`) — absent from the set.

6. **Naming of the frame's byte source.** Arcade: `srcDoc={verifiedBytes}` (`player-security-model.md:39`). Runtime: "verified closure-backed resource URLs or an immutable virtual mount, never Locators or partially verified members" (`app-runtime:622-623`) and a one-shot nonce challenge before any `MessagePort` (`:636-642`).
