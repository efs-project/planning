## 1. Headline

The Media Library set is a coherent, honestly-labelled, owner-directed *product decomposition* (shared media infrastructure + Booru app + Plex/Jellyfin app) written on 2026-08-14 over the Stage A B0 proposal, with a small evidence-gated inbox and two dated media rulings. It is not on the MVP path: its own inbox defers first-product scope to `V2-F2`, no media trace appears in the constitution's acceptance tests or in V2-F2's named traces, and Stage B has not measured the tag write/read bundle that every public-query promise in the set rests on. Internally the three design docs agree on privacy, verification and exit; they disagree on where "Edition" sits in the identity tree and on resolver state vocabularies. The set's Core assumptions are mostly generic (B0 `SCALAR_EQ`/`REF_BACKLINK`/`DIGEST_EQ`, `ChunkTree/1`, Binding/Lens point reads), but two asks hide inside generic wording — a *same-basis* tag-membership point probe / count-at-basis and a "workload-proven small compound key" — both of which B0 explicitly does not provide. The query ladder matches the 2026-07-15 "lean hard on-chain / The Graph only for heavy search" ruling and survives the 2026-08-12 reset because it treats July mechanisms as historical and re-earns The Graph through a dated 2026-08-14 media ruling. The set's biggest external defect is that its build-order step 1 (Foundation Slice 0) and its only "current tiny local proof" point at a spec in `experiments/…` outside the vault, in a no-remote repository; the set's dependency line still names the historical `clientv2` set instead of `web-client-os`.
