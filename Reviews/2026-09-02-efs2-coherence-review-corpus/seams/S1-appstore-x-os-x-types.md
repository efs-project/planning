## 4. Q4 — Is the Store on the File Browser MVP critical path?

**No.**

- Owner direction 2: "The first MVP must be an official write-capable File Browser … Guest reading remains independent of that path" (`web-client-os/README.md` l.44-47).
- `mvp-and-acceptance.md` l.95-100: "package installation, third-party executable Views, full Session Shell, Arcade Play … shared-profile Try, Adopt, Fork or Activate, whole-system configuration management … Their object and authority seams are reserved now, but none is required to ship the File Browser MVP"; l.843-851: Store is a consumer "of the skeleton, not MVP features".
- OS work sequence: "Full Try, whole-system activation/rollback, thousand-module and Component/WASI execution experiments gate their later product lanes, not the Files MVP" (`README.md` l.473-478).
- Store: "Build no production registry" (`README.md` l.228); Kanban card in Backlog (`Kanban.md` l.13-14).
- The first-party client release stays outside the Store: "neither local object is folded into `PackageHandoff` or the first-party `AppReleaseGeneration`" (`architecture-and-modules.md` l.671); `ReleaseClosure`/`ChannelEnvelope` (l.719-732) satisfy direction 19 (`README.md` l.107-117) without any Store object.

**Minimum the MVP borrows.** Nothing Store-owned. The only shared material is the Core content vocabulary — `ArtifactClosure/1`, `ByteDigest/1`, `ChunkTree/1`, `Locator/1` (`b0-content-locators.md`; Store row l.822; OS `mvp-and-acceptance.md` l.143) — owned by efsv2 and proposal-only. The MVP also inherits the *Type-arm question* through Files, not through the Store.

**Freeze-as-later (names only, no bytes):** the one-way `PackageHandoff` field/exclusion list (`architecture.md` l.525-554); the `InstallBindingGeneration` + `InstallStatusLedger` split; one `RuntimeRequest` per activation unit; the "handoff has no semantic identity yet" hold.

**Cut from any plan inside a year (F7):** delta-chain `CatalogEdition` (l.345-353, 373-378); `UpdateTrustPolicy`/`UpdateTrustState` TUF roles/thresholds/epochs/cooldowns (l.401-435); "Deployable EVM helper/module" profile (l.502, 513-523; added by `da0aec2` from the branch-only SDK census); remote-connector and tool/agent profiles (l.503-504); SLSA/in-toto/Sigstore/SPDX/CycloneDX evidence profiles (l.384-386, 765-766); TS+Rust 10k resolver and 100k+1M-spam catalog fixtures (l.933-934); `PresentationOffer` (l.584-605); the Store's "Candidate product MVP" as a product (l.859-903); on the OS side, `SystemProfileRecipe`'s package-range/channel/catalog inputs (l.227-231) until a resolver exists.

## 5. Findings

### F1 — UNDECIDED · important · MVP-relevant · owner: efsv2 (arm) + open-web-app-store (arm-neutral statement) · neighbours: web-client-os, owner
**The Store's written mapping is B0, its executed evidence is layered, the OS packet is layered-in-all-but-name, and nobody has said which fields perturb package identity under each arm.**
Evidence: `architecture.md` l.53-55, 816, 818-830, 854-857 (B0); fixture README l.7, 13, 66, 70-141 (layered); Store README l.183-184 ("for this arm"); `type-data-abi-boundary-pressure.md` l.48-50 (neutrality claim) vs l.159-173, 504-517, 580-584, 603-604 (C-shaped fields, controls lifted from the fixture); `core-architecture-candidate.md` l.291-292 ("Under Type Variant A, a new canonical index means a new Type Schema") contradicts the fixture's Queries row under B0; `layered-…` l.215-217 and l.1234-1237 require A as control — no B0 control run; `owner-rulings.md` l.208-210 and direction 12 (`web-client-os/README.md` l.95-99) keep the arm open; Files (`hierarchical-files-and-folders.md` l.671-676) is B0-only.
Consequence: if the disposable dev Realm mints B0 Types (the only arm Files defines), the Store's only executed evidence does not apply to it. Fix: efsv2 — write down which arm the disposable Realm mints; open-web-app-store — run the same fixture on a B0/Variant-A control or add an arm-neutral identity table (which of Manifest/closure/ceiling/profile-ID/label/index declarations perturb `PackageRelease`/`ResolvedPackageSet` identity under each arm); web-client-os — label the descriptor and TDAB-E1/Q1 as Architecture-C-shaped or add a B0 variant.
