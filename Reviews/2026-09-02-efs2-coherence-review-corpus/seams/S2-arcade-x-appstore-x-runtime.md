### 1.2 Identity rules compared

- **Arcade v1:** identity is the slug plus a bare sha256; chain values live only in a receipt; "No required chain values" (`mvp-architecture.md:118`); update = PIN supersession at the same slot; fork = new slug with `forkOf` (`:75`).
- **Core candidate:** `RecordId = H(domain, typeSchemaId, canonicalBody)` (`core-architecture-candidate.md:115`); a `GameRelease` is a Record referencing Project + closure; ten curators endorsing the same Release share one RecordId and keep ten Occurrences (`:176-181`).
- **Stage A:** `ArtifactRelease/1.versionLabel` is *inside* the Record body and commented "testimony" (`b0-content-locators.md:791`) — but under the RecordId formula it is identity-bearing: same bytes with a different label = a different Release.
- **Store:** OWS-R4 "Labels such as `1.2.3` are testimony, never identity or global ordering" (`architecture.md:74`); "Changing the manifest, requested capability ceiling, profile/schema ID, payload bytes, or Project creates a new Release. Changing a Locator… does not" (`:251-254`); the label's role in identity is not listed either way (R12 lane finding F2 already records this contradiction).
- **Andromeda makes the abstract question concrete:** "'Version 0.9.0' maps to two different byte sequences… An exact Project/Release/Art[ifactManifest] identity must pin the digest, not the version string" (`Reviews/2026-08-13-claude-evidence-round/corpus/arcade/andromeda-evidence-reproduction.md:24`, `:63`).

### 1.3 Who owns catalog/curation

Three shapes, none chosen for Arcade: (a) per-member `CatalogMembership` Occurrences plus a per-Project `SelectedRelease` Binding (Core candidate `:377-378`; Stage A `:729-730`); (b) an immutable `CatalogRelease` over a finite materialized/delta `CatalogEdition` with one Binding per *catalog*, which the store prefers "rather than one Binding per mutable entry" and says a live per-position catalog "requires the Files proposal's unproven `BindingScope` experiment" (`architecture.md:364-378`); (c) the Arcade's v1 build-baked manifest + curator lens. The store says "Arcade, Media, Nanda, EAP, and other PMs own their application semantics" (`open-web-app-store/README.md:124`), the runtime says the same (`web-client-os/README.md:414`; `app-runtime-and-direct-launch.md:762-764`), and the store's checklist requires "Arcade… owners review their boundary slices" (`README.md:264-265`; `architecture.md:1011`) — but the store also lists Arcade under "Consumer pressure already incorporated: the same exact Release/closure supports guest Play and local install" (`README.md:188-192`). Nobody on the Arcade side has reviewed, adopted, or rejected that.

2. **"Verify-before-execute" as an exact-execution claim.** Container is `srcDoc={verifiedBytes}` (`:39`), a `<meta>` CSP is rejected because it "mutates the verified bytes before render" (`:50`), "Outbound network is NOT blocked" (`:50`), invariant "no bytes render unverified" (`:73`) — and the doc's own post-review qualification: "'no unverified bytes' covers what is *mounted as the document*. A sandboxed frame with open egress could still `<script src>`, `fetch`+eval, or navigate itself to remote content — unverified code inclusion the hash check cannot see" (`:112`), with curation as the control. The runtime spine says exactly this profile "is a separately labelled remote-code session, not an exact-qualified App launch" (`:66-68`), is "explicitly `DIRECT_EGRESS`" absent "a measured, cross-browser dedicated-origin/CSP design" (`:646-648`), and "If direct egress lets the App fetch and interpret mutable instructions… the session is labelled `MUTABLE_REMOTE_EXECUTION_OR_DATA`, requires explicit Launch, and loses exact-execution, offline and reproducibility qualifications" (`:656-661`); the skeleton "is falsified if… iframe direct egress is called network-denied" (`:1003`). The measurement confirms the mechanism on both engines: `fetch(... no-cors)` to the public internet works, WebSocket is "fully functional, no CORS gate" (`browser-runner-measurements.md:83`, `:86`), and "self-nav to external `https://`… navigates… The landing document inherits the sandbox and the opaque origin" (`:104-108`). The candidate game itself does this: on its info screen "`window.location = SOURCE_URL` when the user clicks the displayed URL line. **The game will try to navigate its own frame to github.com**" (`andromeda-evidence-reproduction.md:96`). 3. **Process isolation.** T5: "srcDoc frames typically share the parent renderer process — a hostile tight loop can hang the tab; recovery is tab reload. Accepted at demo scope" (`:31`). Measured: Chrome puts the opaque sandboxed frame out of process (51 ms host gap on a 3 s busy loop); Safari freezes the host 3,027 ms (`browser-runner-measurements.md:150-164`). The runtime spine states the honest version — "Frame removal is best-effort browser teardown, not proof that the frame had a separate renderer/process" (`:707-710`) — but neither doc records the engine split, and the runtime's §"Current primary evidence" (`:1037-1089`) lists only external sources (the vault's own measurement file is cited by no `Designs/` document; grep re-run).
4. **Frame-rate/timer throttle.** Safari runs any cross-origin child at ~22 rAF/s and ~34 10-ms timer ticks/s while the host runs 60; "The Safari penalty follows cross-origin-ness, not the sandbox attribute" (`:173-185`). Andromeda uses a "`setTimeout`-driven loop (not rAF) at 50 fps" (`andromeda-evidence-reproduction.md:106`) — timer-capped in Safari. Neither `player-security-model.md` nor the runtime spine mentions throttling; the Arcade's mobile posture (README `:15-16` "mobile-capable… remain targets"; `september-plan.md:95` acceptance 1 on "iOS Safari or Android Chrome") has no Safari row, and the memo tested "one browser tuple (Chromium-family desktop + emulated mobile)… No Safari/iOS WebKit or Firefox verification" (`:107`). iOS, Android, Firefox, touch and gamepad are "entirely unmeasured" (`browser-runner-measurements.md:205-216`). Owner direction #15 requires lagging engines to "receive an explicit reduced/unsupported outcome or rescue path" (`web-client-os/README.md:92-95`) — nobody has written that outcome for the Arcade frame.
5. **Fullscreen.** Arcade defers shell-owned fullscreen (`:82`) and Andromeda calls `canvas.requestFullscreen()` on `f` (`:96`). Measured: `allow="fullscreen"` alone → disabled in Safari; legacy `allowfullscreen` alone → enabled; both → disabled (`:137-148`). The runtime spine requires gesture-gated actions to "use a runner profile fixed at construction and tested for that gesture" (`:277-280`) — no such profile text exists on either side.
6. **Construction mechanism.** Arcade mounts via `srcdoc`; the runtime requires "verified closure-backed resource URLs or an immutable virtual mount, never Locators or partially verified members" (`:622-623`), records the "construction/CSP/blob mechanism" in `RunnerRealization` (`:605`), and lists `srcdoc` on its *unmeasured* research queue ("Build the malicious iframe matrix on dedicated/static/CID origins, `srcdoc`, blob and closure-backed resource models", `:1022-1025`). For one 45,248-byte file `srcdoc` may well be the simplest immutable mount, but no document says so.
7. **Venue/placement.** `:10` "Ephemeral-tier client work in `contracts/packages/nextjs`" is displaced by the greenfield ruling (`Decisions.md:23`) and by the README's own "placement… remain open" (`:20`); the runtime's home for this is the Minimal App Host (`:308-312`) reserved by the MVP but "not yet implement[ed]" (`:847-853`).

### 4.3 Verdict on sequencing (inference, stated as recommendation)

Split the "one-game slice" into three things that have different dependencies:

1. **A Core-level disposable trace** — Andromeda's digest, two Locator Records, one `ArtifactClosure`, one Release, one curator Binding, a tampered-primary rejection by a verifier, a second-implementation rebuild — is client-agnostic (ETHOnline trace items 2–5, `ETHOnline-2026.md:52-56`) and needs only Stage B fixture bytes. It can **accompany** the File Browser as a Stage B fixture and should replace Stage A's wasm-shaped `FX-ARC` artifact, or sit beside it. It needs no runner and makes no product claim.
2. **A client-hosted Play** (detail route, opaque frame, egress label, Safari row) should **follow** the File Browser's route parser, Reader/Verifier and trusted host role, which the runtime spine says the MVP ships and the Arcade fixture reuses (`app-runtime-and-direct-launch.md:847-853`), and it needs the separate authorization the spine names (`:857`).
3. **A product slice** (catalog, curation workflow, comments, brand, outreach) should not be built now (§4.4).

Doing 1 now does not conflict with direction #2; doing 2 before the File Browser would freeze a route grammar, package identity and runner profile the runtime calls "deliberately unfrozen" (`:107`) and would collide with the MVP's "Guest bundles contain no… Arcade" rule (`:514`).
