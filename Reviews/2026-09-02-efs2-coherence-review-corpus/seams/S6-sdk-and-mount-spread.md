# S6 — SDK and OS-drive/mount spread (cross-cutting seam, 2026-09-02)

Lane `S6-sdk-and-mount-spread`. Vault read-only (`main` @ `234c3e6`, 2026-08-30). Every claim below was re-checked at the source; map claims were used only as pointers. Off-`main` facts were read through the GitHub API (no fetch into the vault's `.git`). "Inference" is marked where I infer.

## Verdict: **broken** (SDK half) / **strained** (mount half)

The vault's product, Files, Type, and Ethereum-standards sets all lean on an "SDK" — the MVP write journey lazily loads an SDK-shaped "identity/controller resolver, action planner, signer ceremony, submitter" (`Designs/web-client-os/mvp-and-acceptance.md:61-62`), the Files proposal assigns the SDK "canonical codec/resolver/view/citation/acquisition APIs" (`Designs/efsv2/hierarchical-files-and-folders.md:2276`), the Type proposal has the SDK "emit canonical Record + Envelope + AdmissionIntent" (`Designs/efsv2/layered-type-system-and-data-abi.md:143`), and the Ethereum map makes the "Protocol SDK" lowest owner of five of seven MVP evidence needs (`Designs/web-client-os/ethereum-standards-and-interop.md:546-553`). **No document on `main` designs that SDK.** Every root `Designs/sdk-*.md` is a June 2026 v1/EAS-era document (`Designs/README.md:72-75` banner: "not EFS 2.0 inputs by default"); `Designs/clientv2/sdk-boundaries.md` is July evidence built on the retired kind table; and the one EFS v2 SDK design set that does exist — `Designs/sdkv2/` (11 files) — lives only on the unmerged remote branch `codex/sdkv2-pm` (`57d04f8`, 2026-08-25), invisible to the content map, Kanban, tri-sync, and `Open-Decisions.md`, while four `main` documents cite it by GitHub permalink. Three placement questions (who owns the Files resolver; who owns plan → sign → submit → receipt → read-back; which of four result vocabularies is the law) are answered differently by the client set, the Files proposal, and the branch. The mount half is better: the three-host read-only requirement is owner-adopted, explicitly wired into `hierarchical-files-and-folders.md`, and correctly deferred from the MVP — but it has no design home, lane, card, or owner, its July design document mixes the adopted outcome with superseded mechanisms and a stale venue, and the ruling makes three native daemons a gate on the *first permanent release* while the roadmap puts them in the *long-term* horizon.
