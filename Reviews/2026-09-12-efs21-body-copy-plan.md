# Bounded Record-body copy optimization

> Staged, not dispatched. Use `superpowers:subagent-driven-development` for one bounded implementation, independent review and root reproduction. Re-pin to the reviewed shared-byte result. No measured saving yet.

**Goal:** remove byte-at-a-time copying from the actual structural validator without changing its language, logical output, references, indexes or authority. Price whole full-C0 operations as well as the helper call.

**Architecture:** change only `RecordBody.slice` to an exact-length bounded MCOPY into the existing Solidity-allocated result. `TypeGroupParser.slice` and `StateKernel.group`'s prefix-removal loop remain unchanged. This is a helper-copy experiment, not a storage-format or semantic-profile change; its authenticated runtime/dependency profile does change.

Source preflight at`987a7bf` found exactly two slice uses: successfully decoded top-level fields and MAP keys. Their source spans follow checked cursor advancement. Public malformed inputs normally fail before slicing. Existing private edge behavior is nevertheless preserved below. Cancun is already the experiment target; [EIP-5656](https://eips.ethereum.org/EIPS/eip-5656) defines exact-length, overlap-safe memory copying, but supplies no Solidity array-bound check. Do not infer a full-operation saving from its opcode price.

## Why do this before more feature sacrifice?

The shared-storage pair shows that large-body operation cost still includes substantial work beyond byte retention. Source inspection found an avoidable copy loop in that path. Measure this implementation inefficiency before attributing all of its cost to the Type system's expressiveness. It is a reversible experiment, not a promise of an order-of-magnitude result.
