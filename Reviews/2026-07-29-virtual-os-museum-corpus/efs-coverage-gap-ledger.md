This is owner-inbox territory (kernel runner set; PAF open question 5), and it is *load-bearing* for the museum, not peripheral. |
| 11 | Runtime-specific capabilities + emulator adapter bridge | **GAP** (client design) | PAF-5 sketches the versioned bridge (handshake, lifecycle, saves). But the kernel capability list has **no audio, fullscreen, pointer-lock, or gamepad capability at all**; timing coarsening is an open question that collides with A/V-sync emulation; canvas is above the guest floor. The emulator adapter (screen/input/disk/audio/save over MessagePort) is genuinely unwritten client/runtime design work. WASI Component WIT as the bridge ABI is attractive but speculative (no precedent anywhere). |
| 12 | Local snapshots and portable saves | **COVERED-WITH-SPEC-DEBT** | Immutable base + dirty-chunk overlay (measured in the wild: OPFS `Saved HD.data` + `.dirtychunks`) fits Tier-A + `storage.kv` + pins; v86 save-states add RAM suspend; PAF-6 honesty rules cover eviction. Debt: single-elected-storage-worker throughput for GB-scale mutable images is unmeasured; overlay save shape should become a blessed content convention. |
| 13 | Browser storage eviction recovery | **COVERED** | PERSIST's three-deletion-authorities analysis, generation sentinels, loss events, honest labels — plus the museum case adds a soft landing VOM lacks: every byte except the save overlay is re-fetchable by content address. |
| 14 | Smoke tests tied to exact browser/runtime generations | **COVERED** (as content convention) | Claim tuple from #7 + PAF-8's browser smoke tests. VOM proves the maintenance economics: ~half of 1,700 installs re-verified at launch, emulator regressions are the top breakage source — plan for continuous re-testing as first-class content ops. |
| 15 | Metadata-only records when bytes can't legally be mirrored | **COVERED** | PAF-7 metadata/link-only records; publisher refuses non-redistributable bytes. The feasibility matrix makes this the *majority posture* for the most-loved classes (Mac, Windows, arcade, consoles) unless the owner adopts a tolerated-hosting stance — which the protocol's no-takedown permanence makes far riskier for EFS than for VOM/IA. |

License caution: VOM metadata is CC BY-NC-SA — an EFS import must respect NC + attribution + share-alike (NEEDS-COUNSEL for anything commercial-adjacent). |

## Protocol-gap verdict (the boundary rule applied)

**No new contract field, kind, or read method is justified by this use case.** The three pressure points are all *reconciliation/spec debts already named in the vault*, now with sharper evidence:

1. **Generation naming** (#2) — answer PAF open question 1; the museum needs it but adds no new shape.
2. **Range-read semantics** (#3) — write the spec text the mount ruling already requires; chunk-granular verification is the existing mechanism.
3. **Bulk-byte economics** — the unproduced gas snapshot (freeze-gates A2) gates the web-archive-economics verdict; GB-scale disk images live off-chain/mirror-tier by the ruled DA boundary, so the museum mostly *reads* through mirrors and pins — but the economics verdict must exist before promising "EFS hosts OS images" rather than "EFS names, verifies, and locates OS images".

Everything else is client, SDK, tooling, or content-convention work — with the **runner-lane owner decision (#10) and the emulator-adapter design (#11)** as the two long poles.
