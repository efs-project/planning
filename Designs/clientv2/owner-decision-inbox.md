## Superseded questions — never revive silently

### N2 — Client v2 as one Web OS

The July thesis proposed Bootstrapper → Kernel → System Chrome → Session Shell
→ apps. That complete package is not automatically adopted. Revalidate its
least-authority, rollback, truthful-grade, and no-ambient-authority outcomes
against the new Web Client / shared modules / optional OS split.

### OS1 — Mainstream authorship onboarding

External wallets, passkey-protected local keys, recovery, and ordinary device
keys remain useful evidence. Exact onboarding waits for the Principal/account
and Web Client write slices; guest reading does not wait for any key.

### OS2 — Agent foundations

Agent sessions, budgets, frozen plans, approvals, outbox integration, and
receipts remain OS evidence. They are not EFS Core primitives merely because a
future OS needs them.

### E7/E8 — Browser lanes and rendering

The cross-browser cage and surface-mode spikes remain evidence tasks for a
future runner/OS pass. They do not choose the direct File Browser or make one
old declarative renderer canonical.

### L1–L7 and CL1/CL2 — launch/product choices

Update trust, dangerous-package boot, endpoint defaults, monitoring, product
name, sovereign endpoint tooling, and translation scope are future product
choices. There is no selected OS launch or beta whose deadline makes them live.
